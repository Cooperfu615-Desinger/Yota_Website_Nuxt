# 第十一章：站內信與系統通知

- 章節狀態：草稿，待產品確認
- 版本：0.1
- 建立日期：2026-08-01
- 適用對象：產品營運人員、客服人員
- 對應功能：站內信列表、分類、讀信、未讀狀態、信件附件、領取附件、刪除信件、批次操作、系統通知、獎勵卡新卡與轉換通知
- 相關章節：第五章「錢包與遊戲幣別」、第六章「儲值與付款」、第九章「每日任務、活動與排行榜」、第十章「獎勵卡與獎勵兌換」

## 1. 本章目的

本章說明玩家如何查看站內信、閱讀系統通知、領取信件附件，以及如何判斷活動公告、儲值通知、獎勵卡提示與轉換通知的差異。內容也涵蓋附件已領取、信件刪除、通知未顯示、未讀數不同步與補償找不到等客服情境。

客服閱讀本章後，應能回答以下問題：

- 玩家從哪裡查看站內信與系統通知？
- 打開信件後是否會自動標記已讀？
- 信件附件有哪些幣別？怎麼領取？
- 為什麼活動補償沒有出現在站內信？
- 信件刪除後能不能恢復或重新領附件？
- 活動公告、儲值入帳通知、獎勵卡新卡提示有什麼不同？
- 未讀紅點沒有出現時，客服應查通知還是查資產？

本章核心原則是：

> 站內信是訊息與部分儲值幣附件的載體，不是所有獎勵的唯一入口。儲值金幣、儲值銀幣或銅幣等結構化附件可以透過信件領取；活動金幣與活動銀幣一律改由獎勵卡派發，不經站內信附件。通知是否顯示，不等同於資產是否已入帳，最終仍需查正式錢包、獎勵卡或交易紀錄。

## 2. 站內信與通知的區分

| 類型 | 主要內容 | 玩家查看位置 | 是否一定有附件 |
|---|---|---|---|
| 系統通知 | 維護、帳號、功能狀態與安全提醒 | 站內信／通知中心 | 否 |
| 營運公告 | 活動、排行榜、版本或服務公告 | 站內信／公告列表 | 否，依活動而定 |
| 帳務通知 | 儲值訂單、付款結果或交易提示 | 站內信／儲值訂單 | 可能有儲值幣附件 |
| 獎勵卡新卡提示 | 活動金幣／銀幣獎勵卡已建立 | 獎勵卡未讀提示 | 不放在信件附件，直接進獎勵卡 |
| 轉換完成通知 | 獎勵卡完成流水與轉換結果 | 獎勵卡頁通知 | 轉換結果已入對應儲值錢包 |
| 客服或個案通知 | 依正式產品設計的個別訊息 | 站內信或客服區 | 依訊息內容 |

目前官網的畫面分類為 `system`、`event`、`deposit`，其他平台與後台仍有不同分類名稱。客服說明時應使用玩家看得到的中文分類；若查 API 或後台資料，需依正式型別對照表判讀，不要直接把不同平台 enum 當成相同狀態。

## 3. 使用前提與安全規則

### 3.1 使用前提

- 查看會員個人信件、附件與領取狀態通常需要登入。
- 未登入玩家可能只能看到公開公告，不能查看個人帳務通知或領取附件。
- 登入後應重新載入信件與未讀狀態。
- 信件附件領取必須由玩家本人在正式官網操作，不由客服代為取得驗證碼或付款資料。

### 3.2 安全規則

- 站內信不會要求玩家提供完整密碼、簡訊驗證碼、支付卡安全碼或網銀密碼。
- 客服不會要求玩家點擊私人帳號提供的收款連結來領取補償。
- 玩家若收到要求私下匯款、提供密碼或掃描不明 QR Code 的訊息，應視為可疑內容並回報。
- 信件中的活動連結應確認為官網正式連結；不確定時先不要操作。

## 4. 查看站內信流程

1. 玩家登入官網。
2. 從導覽列、會員中心或大廳入口開啟「信箱／站內信」。
3. 系統載入信件列表與未讀狀態。
4. 玩家依分類查看系統通知、營運公告或帳務通知。
5. 點擊一封信件。
6. 系統載入信件詳情並將該封信標記為已讀（若正式規則採讀信即已讀）。
7. 玩家查看標題、發送時間、正文、活動連結與附件。
8. 若有附件，確認幣別、數量、領取狀態與有效期限（若有）。

> **截圖預留｜11-4-01｜信箱列表、分類、未讀狀態與信件詳情**
>
> - 放置位置：本節查看站內信流程之後。
> - 用途：確認信箱入口、分類、未讀標示、標題、時間、正文、活動連結與附件入口。
> - 狀態：待補正式產品截圖。

### 4.1 信件狀態

| 狀態 | 玩家看到的結果 | 客服說明 |
|---|---|---|
| 未讀 | 列表有未讀標示或紅點 | 打開信件後依正式規則轉為已讀 |
| 已讀 | 內容已查看 | 已讀不代表附件已領取 |
| 有未領附件 | 顯示「領取」按鈕 | 需要另外完成附件領取 |
| 附件已領取 | 顯示已領取或按鈕停用 | 不能重複領取 |
| 已刪除 | 列表不再顯示 | 能否恢復或查詢依正式保留規則 |
| 已撤回 | 可能不再顯示或顯示撤回提示 | 以正式後端通知狀態為準，不把內容重新轉傳給玩家 |

「已讀」與「已領取」是兩個獨立狀態。玩家打開信件但沒有按領取時，附件不應被視為已領取；玩家領取附件但信件列表尚未刷新時，應以附件領取流水與後端狀態為準。

>
> - 放置位置：本節信件狀態表格之後。
> - 用途：對照已讀與已領取的獨立狀態，以及已刪除／已撤回的玩家可見結果。
> - 狀態：待正式狀態文案確認後補截圖。

## 5. 領取信件附件流程

### 5.1 單封信件領取

1. 玩家開啟有附件的站內信。
2. 查看附件幣別、金額與說明。
3. 確認附件尚未領取。
4. 按下「領取」。
5. 系統確認玩家權限、附件狀態與是否已被其他裝置領取。
6. 成功後，附件依幣別加入對應錢包。
7. 附件狀態變為已領取，按鈕不可再次使用。
8. 玩家重新查看錢包與交易紀錄。

> **截圖預留｜11-5.1-01｜單封信件附件領取流程**
>
> - 放置位置：本節單封領取流程之後。
> - 用途：確認附件幣別、金額、領取按鈕、處理中、成功／已領取與錢包／交易紀錄入口。
> - 狀態：待補正式產品截圖。

### 5.2 信件附件允許的幣別

依正式決策，信箱附件可以承載結構化的儲值金、儲值銀或銅幣：

| 附件 | 領取結果 | 注意事項 |
|---|---|---|
| 儲值金幣 | 加入 `gold.stored` | 依正式附件金額入帳 |
| 儲值銀幣 | 加入 `silver.stored` | 依正式附件金額入帳 |
| 銅幣 | 加入 `bronze` | 仍是無價值試玩幣 |
| 活動金幣 | 不經信箱附件派發 | 由獎勵卡承載 |
| 活動銀幣 | 不經信箱附件派發 | 由獎勵卡承載 |

如果信件內容寫著活動補償，但玩家找不到活動金幣附件，應先確認是否已改由獎勵卡派發，而不是直接判定補償遺失。

> **截圖預留｜11-5.2-01｜信件附件允許幣別與活動幣排除提示**
>
> - 放置位置：本節附件幣別表格之後。
> - 用途：確認儲值金幣、儲值銀幣、銅幣可透過附件領取，以及活動金幣／銀幣改由獎勵卡派發的提示。
> - 狀態：待補正式產品截圖。

### 5.3 領取後確認

1. 查看信件是否顯示已領取。
2. 查看對應錢包餘額。
3. 查看交易紀錄是否產生 `REWARD_CLAIM` 或正式對應類型。
4. 若是銅幣，提醒玩家只能用於試玩。
5. 若是活動幣通知，前往獎勵卡頁確認卡片，而不是在儲值錢包尋找。

後端必須防止同一附件被重複領取。玩家重複點擊、刷新頁面或跨裝置領取時，應以唯一正式結果為準，不應造成重複入帳。

## 6. 活動補償與獎勵卡提示

### 6.1 活動幣不經站內信

正式規則已確認：

- 活動金幣與活動銀幣一律發放獎勵卡。
- 補償、推廣或簽到里程碑若發的是活動幣，直接建立獎勵卡。
- 玩家應在獎勵卡頁查看卡片來源、幣別、金額、流水、轉換上限與期限。
- 站內信未讀紅點不是活動幣補償的唯一提示來源。
- 正式產品應提供獎勵卡新卡未讀提示，例如 `/reward-cards/unread`。

這個規則避免玩家看到信件但找不到活動幣，也讓每一筆活動幣都能追溯到卡片規則。

> **截圖預留｜11-6.1-01｜活動幣不經信件附件與獎勵卡入口**
>
> - 放置位置：本節活動幣派發規則之後。
> - 用途：確認活動金幣／銀幣、獎勵卡來源、站內信未讀提示與獎勵卡頁入口的分工。
> - 狀態：待補正式產品截圖。

### 6.2 新卡提示流程

1. 系統建立新的獎勵卡。
2. 獎勵卡服務產生未讀新卡提示。
3. 玩家登入或開啟獎勵卡頁時查詢未讀提示。
4. 玩家進入卡片明細，查看來源與規則。
5. 玩家將新卡提示標記為已讀。
6. 卡片仍依本身狀態存在，不會因提示已讀而自動啟用或轉換。

> **截圖預留｜11-6.2-01｜新獎勵卡未讀提示與卡片明細**
>
> - 放置位置：本節新卡提示流程之後。
> - 用途：確認新卡未讀數、卡片來源／規則、標記已讀與不自動啟用／轉換的狀態。
> - 狀態：待補正式產品截圖。

### 6.3 轉換完成通知

獎勵卡完成有效流水與轉換後，系統應提供轉換通知，至少讓玩家知道：

- 哪一張卡完成轉換。
- 原始活動幣餘額。
- 實際轉入儲值錢包的數量。
- 依轉換上限回收的數量。
- 轉換時間與目標錢包。

通知本身是結果說明，不取代正式 `BONUS_CONVERT` 與儲值錢包流水。若通知與流水不同，客服應以正式流水查核。

## 7. 刪除與批次操作

### 7.1 刪除單封信件

1. 玩家開啟信件詳情。
2. 確認已閱讀內容與附件狀態。
3. 若有未領附件，先確認是否要領取。
4. 按下刪除並確認。
5. 信件從列表移除。

玩家應先領取需要的附件，再刪除信件。刪除信件不應被說成自動領取附件；附件能否在刪除後恢復或透過 API 查詢，需以正式保留規則為準。

> **截圖預留｜11-7.1-01｜刪除單封信件與附件未領提示**
>
> - 放置位置：本節刪除單封信件流程之後。
> - 用途：確認刪除前的已讀／附件狀態、未領附件提醒、刪除確認與刪除後列表結果。
> - 狀態：待正式保留與恢復規則確認後補截圖。

### 7.2 批次標記與全部領取

正式 API 規格可能提供批次刪除與全部領取，但官網目前畫面主要是單封操作。只有當正式前台提供對應按鈕時，客服才能依畫面引導玩家執行批次操作。

若批次領取功能正式開放：

- 系統應逐筆驗證附件狀態與玩家權限。
- 已領取、失效或不符合資格的附件不得重複入帳。
- 玩家應看到成功、失敗或部分成功的結果摘要。
- 客服不能把「全部領取」解釋成會領取獎勵卡活動幣，因活動幣不經信箱附件。

## 8. 通知與入帳的判讀

### 8.1 通知成功不等於資產成功

玩家收到「儲值成功」、「獎勵已送出」或「轉換完成」通知時，客服仍應區分：

- 通知是否建立成功。
- 附件是否已由玩家領取。
- 錢包是否已完成入帳。
- 獎勵卡是否已建立、啟用或轉換。
- 正式流水是否存在且金額正確。

通知延遲、重複或未顯示時，不應直接修改資產；先查正式交易或獎勵資料。

> **截圖預留｜11-8.1-01｜通知、附件、獎勵卡與錢包流水的判讀**
>
> - 放置位置：本節通知與入帳判讀之後。
> - 用途：對照通知建立、附件領取、錢包入帳、獎勵卡建立／轉換與正式流水。
> - 狀態：待補正式查詢畫面或玩家可見畫面。

### 8.2 已讀、已領取與刪除的關係

| 動作 | 已讀狀態 | 附件狀態 | 資產結果 |
|---|---|---|---|
| 打開信件 | 變為已讀 | 維持未領取 | 不入帳 |
| 按領取成功 | 通常已讀 | 變為已領取 | 依附件幣別入帳 |
| 刪除未讀無附件信 | 信件移除 | 無 | 不產生資產異動 |
| 刪除已讀未領附件 | 信件移除 | 依正式規則 | 不應假設自動入帳，先查狀態 |
| 新獎勵卡提示已讀 | 提示變已讀 | 卡片狀態不變 | 不會自動啟用或轉換 |

## 9. 常見情境與處理矩陣

| 玩家情況 | 玩家可能看到的結果 | 客服第一步 | 後續處理 |
|---|---|---|---|
| 未登入查看信箱 | 顯示登入提示 | 引導完成登入 | 登入後重新載入個人信件 |
| 有新信但沒有紅點 | 列表有未讀但導覽列沒有徽章 | 查信件清單未讀欄位 | 徽章缺失升級，不代表信件不存在 |
| 打開信件後未讀變已讀 | 正文可查看 | 說明已讀與附件領取分開 | 未領附件仍可依規則領取 |
| 按領取後餘額未增加 | 按鈕顯示處理中或已領取 | 查附件狀態與 `REWARD_CLAIM` 流水 | 若已領取但未入帳，升級帳務 |
| 按領取時顯示已領取 | 可能由其他裝置先完成 | 查正式附件狀態與入帳時間 | 不重複領取，依唯一結果回覆 |
| 玩家重複點擊領取 | 顯示重複或按鈕停用 | 查是否已有成功領取 | 不重送請求，確認冪等結果 |
| 信件附件是活動金幣 | 玩家找不到活動幣或畫面提示不同 | 確認正式派發來源 | 活動幣應改查獎勵卡，不以信箱直接補發 |
| 收到補償但信箱沒有信 | 補償可能以獎勵卡發放 | 查獎勵卡列表與新卡提示 | 若卡片也沒有，升級補償／獎勵資料 |
| 信件被刪除 | 列表不再顯示 | 確認刪除時間、信件 ID 與附件狀態 | 依保留規則查詢，不承諾恢復 |
| 未領附件的信被刪除 | 玩家想取回附件 | 查附件是否已領取與後端紀錄 | 若未領取，依正式刪除規則處理；不自行補發 |
| 儲值通知已到但金幣未到 | 信件顯示成功、錢包沒有入帳 | 查儲值訂單與 `DEPOSIT` 流水 | 依第六章儲值流程升級 |
| 轉換通知未出現 | 獎勵卡可能已轉換 | 查卡片狀態、`BONUS_CONVERT` 與儲值錢包 | 通知缺失與資產缺失分開處理 |
| 信件內容與活動頁不同 | 舊公告、版本或快取差異 | 記錄信件 ID、活動 ID 與時間 | 以正式活動規則與最新公告為準 |
| 收到可疑站內信 | 要求私下付款或索取密碼 | 請勿點擊並保留畫面 | 回報資安／產品，不依信件操作 |
| 信件未讀數跨裝置不同 | 一台已讀、另一台未讀 | 查讀取時間與同步狀態 | 以後端正式 read 狀態為準 |
| 信件附件幣別錯誤 | 顯示金／銀／銅與預期不同 | 比對附件正式資料與活動規則 | 不自行換幣，升級派發資料 |
| 信件被撤回 | 看不到原文或顯示撤回 | 查後端撤回狀態 | 不提供撤回內容，依正式通知處理 |

## 10. 客服檢查清單

處理站內信或通知案件時，確認：

1. 玩家帳號與身分驗證。
2. 信件 ID、通知 ID 或獎勵卡 ID。
3. 信件類型、標題、建立時間與是否已讀。
4. 是否有附件、附件幣別、金額與 claimed 狀態。
5. 領取操作時間、裝置與是否重複點擊。
6. `REWARD_CLAIM`、`DEPOSIT`、`BONUS_CONVERT` 或其他正式流水。
7. 若是活動補償，確認玩家查過獎勵卡列表與未讀提示。
8. 若是儲值，轉查第六章的儲值訂單與付款狀態。
9. 若是獎勵卡，轉查第十章的卡片期限、流水與轉換狀態。
10. 是否有信件刪除、撤回、跨裝置或通知同步情況。
11. 畫面截圖是否已遮蔽個資、付款資料與驗證碼。

## 11. 客服可直接處理與升級條件

### 11.1 可直接處理

- 引導登入、分類查看、打開信件與確認已讀狀態。
- 說明已讀不等於已領附件。
- 引導玩家領取儲值金、儲值銀或銅幣附件。
- 說明活動金幣／銀幣改由獎勵卡派發，不經信箱。
- 引導玩家查看獎勵卡新卡提示與轉換通知。
- 提醒玩家領取附件後再刪除信件。
- 說明平台不會透過信件索取密碼、驗證碼或私下付款。

### 11.2 必須升級

- 附件顯示已領取但對應錢包沒有入帳流水。
- 附件未領取卻被標記 claimed，或同一附件重複入帳。
- 信件類型、附件幣別與活動／儲值規則不一致。
- 獎勵卡已建立但新卡未讀提示與卡片列表缺失。
- 轉換已完成但通知、錢包或交易紀錄不一致。
- 未讀數、已讀狀態跨裝置不同步且後端資料不一致。
- 信件撤回、刪除或批次操作造成附件狀態不明。
- 疑似釣魚、冒用官方或要求玩家提供敏感資料的訊息。

### 11.3 禁止事項

- 不得把活動金幣／銀幣當成信箱附件直接補發。
- 不得在未查附件狀態前承諾重新領取或補發。
- 不得要求玩家提供密碼、一次性驗證碼、完整卡號或 CVV。
- 不得把「已讀」說成「已領取」或「已入帳」。
- 不得把獎勵卡新卡提示與第八章玩家贈禮混為一談。
- 不得因通知沒有顯示就直接判定正式資產沒有發放。

## 12. 客服回覆範例

### 玩家詢問「我看過信了，為什麼金幣還沒增加？」

> 打開信件會標記已讀，但附件需要另外按下「領取」才會依幣別加入錢包。請先確認附件按鈕是否仍可領取；若已顯示領取成功但錢包沒有對應入帳，請提供信件 ID、領取時間與畫面，我們會查正式獎勵流水。

### 玩家詢問「活動補償為什麼沒有寄到信箱？」

> 活動金幣與活動銀幣目前會以獎勵卡形式派發，不透過站內信附件直接發送。請到獎勵卡頁查看新卡提示、卡片來源與狀態；若獎勵卡也沒有出現，請提供活動或補償資訊供我們查核。

### 玩家詢問「刪掉信件後可以恢復嗎？」

> 請先提供信件標題、信件 ID（若有）、刪除時間與附件是否已領取。我們會依正式信件保留與附件狀態查詢；在確認前，無法承諾刪除後一定可以恢復或重新領取。

### 玩家詢問「收到信件要求我提供驗證碼才能領獎」

> 請不要提供驗證碼、密碼或付款資料，也不要點擊可疑連結。官方不會要求玩家透過私訊提供這些敏感資訊。請保留信件畫面與連結，交由我們進行資安查核。

## 13. 目前系統差異

以下只供內部理解前端 Mock，不可取代正式規則：

- 目前官網信箱使用固定四封測試訊息，重新整理可能回到初始狀態；正式版本應由 `/mailbox` 載入玩家資料。
- 目前官網使用 `system`、`event`、`deposit` 分類，與 APP、後台分類 enum 尚未完全統一。
- 目前官網沒有導覽列未讀徽章消費者，也沒有完整批次全部已讀、全部領取或刪除已讀功能。
- 目前官網支援單封刪除，正式刪除後的信件保留、附件恢復與批次操作仍需依契約確認。
- 目前前端以 `claimed` 欄位與本地狀態防止重複領取，正式版本必須由後端再次執行權限、冪等與資產入帳防護。
- 目前信件附件為測試用的固定金、銀幣；活動金幣／銀幣的正式派發應改走獎勵卡。
- 目前部分信件內容含有 Mock 儲值成功文字，不能用來判定真實儲值訂單已完成。
- 目前獎勵卡新卡與轉換通知尚未完整接入站內信或獨立通知服務，正式位置以產品決策與 API 為準。

## 14. 待產品確認

- 站內信分類與跨平台正式 enum 對照。
- 未讀徽章的顯示位置、計數範圍與已讀同步時機。
- 信件的保存期限、刪除後恢復方式與撤回後畫面。
- 批次全部領取、全部已讀與批次刪除是否在官網正式開放。
- 信件附件的正式幣別、失效期限、領取期限與退款／撤銷規則。
- 活動公告與個人通知的推播、站內信與通知中心分工。
- 獎勵卡新卡提示與轉換通知的獨立入口、未讀狀態與保存期限。
- 通知延遲、重送、重複訊息與跨裝置同步規則。
- 信件被撤回時玩家是否顯示撤回標記、原因或僅從列表移除。
