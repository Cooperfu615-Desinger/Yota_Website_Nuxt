# 第十六章：名詞解釋與規則附錄

- 章節狀態：草稿，待產品確認
- 版本：0.1
- 建立日期：2026-08-01
- 適用對象：產品營運人員、客服人員、文件維護與交接人員
- 對應功能：全官網玩家端功能
- 相關章節：第零章「使用手冊製作規範」、第一章至第十五章

## 1. 使用方式

本章是客服查詢用的名詞表與規則摘要。當玩家使用不同稱呼描述同一問題時，客服可先用本章統一概念，再回到對應章節查看完整流程、例外情況與升級條件。

本章的數值摘要不能取代最新的正式活動條款、支付頁規則、產品決策或 API 契約。若正式來源更新，應先修正對應功能章，再同步更新本章。

## 2. 規則來源優先順序

遇到文件、畫面與目前系統行為不一致時，依下列順序判斷：

1. 已確認的產品目標規則、對外條款與法遵要求。
2. 已確認的前台產品規格與正式 API 契約。
3. 已確認的畫面流程、按鈕名稱與客服公告。
4. 目前前端 Mock 行為，只作為找出開發落差的參考。

「正式產品目標規則」代表產品希望正式上線後，玩家應該依循的規則；「目前前端 Mock 行為」代表現階段為了展示頁面或流程而寫在前端的測試資料與簡化互動。兩者可能不同，例如 Mock 直接把好友加入列表，但正式產品可能需要雙向同意；客服應依已確認的正式規則回答，並把 Mock 落差記錄給產品或技術團隊。

## 3. 帳號與身分名詞

| 名詞 | 定義 | 客服注意事項 |
|---|---|---|
| 帳號 | 玩家登入官網的識別資訊；必填，1–50 個 rune，區分大小寫且為唯一值 | 可使用任何字元，但開頭與結尾不得為空格；不等同於公開暱稱或玩家 ID |
| 玩家 ID | 後端與社交功能辨識玩家的穩定識別碼 | 查詢好友、贈禮、檢舉與案件時優先使用 |
| 暱稱 | 玩家可在公開資料或社交功能看到的名稱；必填，1–100 個字元 | 可以重複，也可以與自己的登入帳號相同；不宜單獨作為查詢鍵 |
| 密碼 | 玩家登入帳號的秘密字串；必填，6–100 個字元 | 允許任何字元；客服永遠不得索取或代為保存 |
| 驗證碼 | 一次性登入、恢復或支付驗證資訊 | 客服永遠不得索取 |
| 玩家代理推薦碼 | 玩家註冊時用於識別代理推薦關係的代碼 | 大寫英數 8 碼；綁定時點與事後變更以正式規則為準 |
| 代理推廣碼 | 代理商對外使用的推廣代碼 | 大寫英數 6 碼；不等同玩家代理推薦碼或活動碼 |
| 活動碼／兌換碼 | 活動或獎勵機制使用的代碼 | 不一定等同推薦碼；先確認輸入頁面 |
| 代理商 | 依合作制度提供推廣或代理服務的合作方 | 不因代理關係取得玩家帳號或付款權限 |
| VIP | 玩家端會員等級與相關權益結構 | 門檻、返利與費率數值以正式制度為準 |

## 4. 遊戲與模式名詞

| 名詞 | 定義 | 常見誤解 |
|---|---|---|
| 遊戲大廳 | 玩家瀏覽、搜尋與進入遊戲的入口 | 進入大廳不代表已進入真錢遊戲 |
| 遊戲模式 | 遊戲執行時的試玩或真錢模式 | 不要以試玩結果推論真錢結果 |
| 試玩模式 | 用於體驗遊戲流程的模式 | 不代表可提領、可兌換或可轉成現金 |
| 真錢模式 | 依正式錢包、下注與結算規則運作的模式 | 需要確認使用的錢包與幣別 |
| 遊戲局／回合 | 一次遊戲進行與結算的單位 | 需以後端局號或交易識別資訊查核 |
| 結算 | 遊戲完成後依結果更新資產的程序 | 客服不能只看玩家主觀描述改判 |
| 遊戲供應商 | 提供遊戲或結果資料的外部服務方 | 前台客服不直接操作供應商後台 |

## 5. 資產、幣別與錢包名詞

### 5.1 資產名稱

| 名詞 | 定義 | 是否等同現金 |
|---|---|---:|
| 金幣 | 平台內主要遊戲／帳務資產之一 | 否 |
| 銀幣 | 可依正式比例與金幣互換的較小單位資產 | 否 |
| 銅幣 | 活動或獎勵用途的資產 | 否 |
| 活動金幣／活動銀幣 | 活動期間發放，可能先以獎勵卡或附件保存的資產 | 否 |
| 獎勵卡 | 保存獎勵資產、轉換條件、目標、限額與期限的卡片 | 否 |
| 主錢包 | 玩家日常查看與遊戲使用的資產位置 | 不是銀行帳戶 |
| 保險箱／金庫 | 玩家存放、兌換或進行贈禮的資產位置 | 不是提款帳戶 |
| 站內信附件 | 隨系統信件發放的資產或物品 | 需先依正式流程領取 |

### 5.2 已確認的換算摘要

- 新台幣 1 元 = 1 金幣 = 100 銀幣。
- 金幣與銀幣的轉換必須從正式錢包／保險箱流程操作，不以聊天訊息或外部轉帳代替。
- 涉及小數或不足最小單位時，依正式規則採無條件捨去，不應自行四捨五入。
- 銅幣是活動／獎勵資產，不可直接當成現金，也不得向玩家承諾可以對外提款。
- 平台正式方向不包含對外現金提款；客服遇到代提、私下換現金或先付款解鎖，應按安全風險處理。

### 5.3 資產位置判讀

玩家說「錢不見了」時，先確認：

1. 是金幣、銀幣、銅幣、活動幣或獎勵卡？
2. 資產原本位於主錢包、保險箱、站內信附件或獎勵卡？
3. 是否剛完成儲值、兌換、遊戲結算、贈禮或領取？
4. 畫面顯示的是可用餘額、凍結餘額、處理中資產還是已完成資產？

## 6. 交易與狀態名詞

### 6.1 通用狀態

| 狀態 | 意義 | 客服說法 |
|---|---|---|
| 待處理／處理中 | 系統或相關單位尚未完成最終判定 | 不代表成功，也不代表失敗；先不要重複操作 |
| 已完成／成功 | 該流程已完成並有正式紀錄 | 仍須確認資產、通知與下游結果是否一致 |
| 已拒絕 | 因資格、規則或查核結果未通過 | 先確認拒絕原因，不承諾人工改為成功 |
| 已取消 | 玩家或系統在完成前取消 | 需確認預扣或凍結資產是否依規則返還 |
| 已過期 | 超過有效期限未完成 | 不等同於系統遺失；依正式期限與補救規則處理 |
| 已結案 | 客服案件不再接受追加內容 | 新問題需建立新案件，並附原案件編號 |
| 未讀／已讀 | 玩家是否已查看通知或客服回覆 | 已讀不等於已領取附件或已完成兌換 |
| 已領取／未領取 | 玩家是否完成取得站內信附件或獎勵 | 不等同於資產已轉換或已能遊戲 |

### 6.2 儲值與訂單狀態

儲值問題要分開看三個結果：

1. 支付平台是否完成付款。
2. 官網訂單是否收到並確認付款。
3. 玩家錢包是否完成入帳。

這三者不同步時，不要要求玩家再次付款，也不要在未查核前承諾補點。客服應以訂單編號、支付狀態、時間、金額、幣別與錢包結果交由金流／帳務查核。

### 6.3 贈禮狀態

| 狀態 | 意義 |
|---|---|
| 待確認 | 贈禮申請已建立，等待收禮方或流程完成必要確認 |
| 已接受／已完成 | 收禮流程通過，依正式紀錄完成資產移轉 |
| 已拒絕 | 收禮方或系統拒絕申請 |
| 已取消 | 申請在完成前被取消 |
| 已過期 | 超過申請有效期限仍未完成 |

贈禮的「申請建立」、「寄件人扣除」、「收件人入帳」與「返還」是不同查核點。玩家提供聊天截圖不等於贈禮完成證明。

### 6.4 客服案件狀態

玩家端主要使用「進行中」與「已結案」。後端可能有未分派、待處理、處理中等內部狀態，除非產品確認對外顯示，否則客服只對玩家說明可見狀態與下一步，不透露內部分派或其他案件資料。

## 7. 獎勵與活動名詞

| 名詞 | 定義 | 判斷重點 |
|---|---|---|
| 每日簽到 | 玩家在指定週期完成一次簽到的活動機制 | 日期、時區、連續／累積規則待正式確認 |
| 每日任務 | 每日或指定期間需完成的任務 | 任務條件、完成紀錄與領取方式 |
| 活動 | 在指定期間與規則下提供的任務或獎勵 | 活動版本、資格、起訖時間與條款 |
| 排行榜 | 依指定統計欄位排序玩家的活動功能 | 統計口徑、更新時間、同分排序與結算時間 |
| 獎勵卡 | 暫存活動資產與轉換條件的卡片 | 卡片狀態、目標、流水、限額、期限 |
| 轉換目標／流水 | 取得獎勵卡後需要完成的有效遊戲量或條件 | 不等同下注金額，也不代表一定可提款 |
| 轉換限額 | 單張或單次可轉換的最大數量 | 超過部分依正式規則處理，不自行承諾補發 |
| WIPE／清理 | 依正式期限或活動週期清除過期資產／紀錄的機制 | 先確認資產是否已過期與公告規則 |

### 7.1 獎勵卡快速摘要

目前規格方向包含活動金幣／銀幣獎勵卡，部分活動節點可能使用第 15 天與第 20 天作為獎勵節點；獎勵卡可能包含 100,000 的轉換目標與 10,000 的轉換限額。以上數值需以正式活動條款與產品確認版本為準，客服不可把其他活動的數值套用到所有獎勵卡。

## 8. 社交與客服名詞

| 名詞 | 定義 | 重要規則 |
|---|---|---|
| 世界頻道 | 公開玩家聊天頻道 | 不公開敏感資料，不私下收款 |
| 私人訊息 | 玩家與特定玩家的一對一對話 | 不等同贈禮或轉帳流程 |
| 客服頻道 | 玩家查看與追蹤客服案件的入口 | 同一時間最多一件進行中案件 |
| 好友 | 玩家之間的社交關係 | 正式是否需雙向同意待確認 |
| 封鎖／黑名單 | 玩家停止或限制與指定玩家互動的安全功能 | 封鎖會同步移除好友 |
| 解除封鎖 | 移除社交封鎖狀態 | 不會自動恢復好友 |
| 檢舉 | 將玩家行為提交平台審核 | 送出不代表一定處分，不能查看他人內部結果 |
| 客服案件 | 玩家針對個人問題提出的可追蹤回報 | 第一則訊息不可空白，結案後依規則建立新案 |

## 10. 待產品確認清單

以下項目若未完成決策，客服只能說明「目前依正式規則查核」，不可自行補充：

- 年齡確認的正式年齡門檻、保存方式與不同地區規則。
- 密碼的長度計算是否同樣以 rune 為單位、恢復連結有效期限與驗證失敗次數。
- 玩家代理推薦碼註冊後補填／更換、歸屬判定與獎勵。
- 代理推廣碼的產生、停用、有效期限與重複使用規則。
- VIP 各級門檻、返利、P2P 費率、費率單位與適用時間點。
- 每日簽到的時區、連續或累積判定、補簽與重置規則。
- 活動獎勵卡的所有面額、轉換目標、限額、流水與 WIPE 時點。
- 儲值支付方式、訂單狀態映射、退款與沖正流程。
- 兌換、資金轉移與贈禮的每日、單筆、VIP、餘額與申請限制。
- 好友邀請是否需要接受、邀請期限、最近遊戲公開欄位與隱私設定。
- 世界／私人訊息的字數上限、敏感詞動作、發送頻率與禁言規則。
- 檢舉是獨立案件或客服案件、理由 code、證據保存與玩家可見狀態。
- 客服案件通知、附件、狀態、結案、重新開案與正式 SLA。
- 代理商推薦、佣金、結算、提款、後台權限與玩家授權代辦規則。

## 11. 不可對外承諾事項

- 尚未確認的 VIP、代理佣金、推薦獎勵或活動獎勵數值。
- 未查核前的補點、退款、改判、解鎖、改代理歸屬或延長期限。
- 任何固定客服回覆、金流入帳、退款或遊戲結算時間，除非有正式公告或 SLA。
- 玩家可以將平台幣別兌換為現金、由代理商代提或透過私下轉帳完成交易。
- 檢舉一定成立、對方一定封號或可以查看對方內部處分。
- 客服可以看到或要求玩家提供密碼、驗證碼、支付密碼、完整卡號或第三方帳密。
- 目前 Mock 畫面出現的測試名稱、測試玩家、假餘額、假通知或 session 狀態就是正式紀錄。

## 12. 文件維護規範

每次產品規則或前端流程變更後，文件維護人員應：

1. 記錄變更日期、來源與影響的功能。
2. 先更新對應功能章的正式規則與例外矩陣。
3. 更新本章的名詞、速查表與待確認清單。
4. 檢查第十五章的話術是否仍提供正確入口與限制。
5. 若畫面改變，將相關截圖標記為待重拍，不使用舊畫面作為證據。
6. 若只有 Mock 改變，保留正式規則並更新「目前系統差異」。
7. 由產品負責人確認後，更新版本號與變更紀錄。

建議變更紀錄至少包含：版本、日期、變更章節、變更原因、確認人、是否影響客服話術與是否需要重拍截圖。
