# 第三章：遊戲大廳與遊戲進行方式

- 章節狀態：草稿，待產品確認
- 版本：0.1
- 建立日期：2026-07-31
- 適用對象：產品營運人員、客服人員
- 對應功能：遊戲大廳、遊戲搜尋與分類、遊戲詳情、遊戲啟動、遊戲畫面、離開遊戲
- 相關章節：第四章「試玩模式與真錢模式」、第五章「錢包與遊戲幣別」

## 1. 本章目的

本章說明玩家如何在遊戲大廳找到遊戲、查看遊戲資訊、啟動遊戲、選擇本次遊戲使用的錢包，以及在遊戲中返回大廳或遇到遊戲無法啟動時如何處理。

本章先聚焦「遊戲入口與進入流程」。試玩模式與真錢模式的幣別價值、資金扣除與結算差異，統一放在第四章說明；各種錢包與幣別的詳細定義，統一放在第五章說明。

客服閱讀本章後，應能回答以下問題：

- 遊戲大廳有哪些主要區域與找遊戲方式？
- 玩家如何使用分類、搜尋、供應商與排序找到遊戲？
- 點擊真錢遊玩後，為什麼會先要求登入或選擇錢包？
- 遊戲啟動前需要確認哪些條件？
- RTP、波動性、最大倍數與賠付線應該如何解釋？
- 遊戲載入失敗、維護、餘額不足或幣別不支援時，客服如何判斷？
- 遊戲中斷或玩家不確定是否完成下注時，需要記錄哪些資訊？

## 2. 遊戲大廳功能總覽

正式產品的遊戲大廳應由遊戲 catalog 提供可上架的遊戲資料，而不是由客服或玩家自行推測遊戲數量。

遊戲大廳主要包含：

- 遊戲分類與分類導覽。
- 遊戲搜尋。
- 供應商篩選。
- 排序功能。
- 遊戲卡片。
- 遊戲名稱、簡介、供應商與標籤。
- RTP、波動性、最大倍數、賠付線等遊戲資訊。
- 最近遊玩的遊戲。
- 真錢遊玩的遊戲啟動流程。
- 試玩的遊戲啟動流程。

### 2.1 目前已確認的遊戲資料方向

正式遊戲資料預計由下列資訊組成：

- 遊戲識別 key。
- 遊戲名稱與簡介。
- 遊戲分類。
- 遊戲供應商。
- 遊戲圖片與顯示排序。
- 行銷標籤，例如熱門、新上線或活動。
- 遊戲狀態，例如可遊玩或維護中。
- 最低 VIP 等級。
- 支援的遊戲幣別。
- 遊戲詳情、規則、RTP、波動性、賠付線與最高倍率。

遊戲 catalog 的正式分類數量、遊戲總數與最終上架範圍尚未確認，因此客服不得以目前原型畫面中的遊戲數量作為「正式共有幾款遊戲」的回答。

## 3. 進入遊戲大廳

### 3.1 正常流程

1. 玩家從官網首頁、主選單或遊戲相關入口進入遊戲大廳。
2. 系統顯示遊戲大廳首頁。
3. 玩家可以瀏覽熱門、最新、分類或最近遊玩的遊戲。
4. 玩家選擇一款遊戲，查看遊戲卡片資訊。
5. 玩家選擇「試玩」或「真錢玩」。
6. 系統依玩家選擇的模式進入對應流程。

### 3.2 未登入玩家

- 未登入玩家可以瀏覽遊戲大廳與查看遊戲資訊。
- 未登入玩家選擇真錢遊玩時，系統應先要求登入或註冊。
- 登入成功後，系統應盡量返回玩家原本選擇的遊戲與操作目的地。
- 若登入後未能自動返回，客服可請玩家重新進入遊戲大廳並再次選擇該遊戲。
- 是否允許未登入玩家直接進入試玩，依第四章的正式模式規則處理。

> - 用途：確認未登入狀態仍可瀏覽的區域，以及點擊真錢遊玩後的登入導引入口。
> - 狀態：待補正式產品截圖。

### 3.3 已登入玩家

- 已登入玩家選擇真錢遊玩時，系統進入遊戲啟動與錢包選擇流程。
- 已登入玩家若有資格使用試玩，可以依正式模式規則直接進入試玩流程。
- 登入狀態不代表玩家一定具備所有遊戲的 VIP、幣別或餘額資格。

> - 狀態：待補正式產品截圖。

## 4. 尋找遊戲的操作方式

### 4.1 使用分類

1. 玩家在遊戲大廳開啟分類選單。
2. 選擇全部、熱門、最新或特定遊戲類型。
3. 系統只顯示符合分類條件的遊戲。
4. 玩家可以再使用搜尋、供應商或排序縮小結果。

正式分類名稱與分類數量以遊戲 catalog 和分類 API 回傳為準。若玩家看不到原本的分類，客服應先確認該分類是否仍在正式上架範圍，而不是直接判定為系統遺失遊戲。

### 4.2 使用搜尋

玩家可以使用遊戲名稱、遊戲簡介或供應商名稱搜尋。

建議搜尋流程：

1. 在搜尋欄輸入完整或部分關鍵字。
2. 玩家按下搜尋後，系統以模糊比對方式篩選符合的遊戲。
3. 玩家確認遊戲名稱、供應商與分類。
4. 選擇遊戲卡片進行查看或遊玩。

> 規格確認注記（2026-08-03，核心行為已確認）
>
> 已取得的規格資訊：搜尋以模糊搜尋為主，玩家按下搜尋後才顯示搜尋結果，不採用僅輸入文字就即時更新結果的說法。
>
> 尚待產品與後端確認：
> - 模糊搜尋實際涵蓋的欄位，是遊戲名稱、遊戲簡介、供應商名稱，或由後端另行定義。
> - 是否支援按下 Enter 送出搜尋。
> - 搜尋欄為空時的結果、清除搜尋後的恢復方式，以及無結果時的正式文案。
> - 大小寫、前後空格、全半形字元與特殊符號的比對規則。

若搜尋沒有結果：

- 請玩家確認拼字、空格與輸入語言。
- 請玩家先清除搜尋欄，再改用遊戲分類瀏覽。
- 若多位玩家同時搜尋不到同一款已公告遊戲，應記錄遊戲名稱並升級查詢 catalog 狀態。

### 4.3 使用供應商篩選

1. 玩家開啟供應商篩選。
2. 選擇一個或多個供應商。
3. 系統只顯示所選供應商的遊戲。
4. 玩家可以取消供應商條件，恢復全部遊戲。

供應商名稱由正式系統提供。客服不得因同一款遊戲在不同供應商版本中名稱相近，就自行判定兩者一定是同一款遊戲。

>

> - 用途：確認單選／複選方式、目前套用條件、清除條件與篩選後的遊戲清單。
> - 狀態：待補正式產品截圖。

### 4.4 使用排序

正式版本可能提供熱門、最新、名稱升冪或名稱降冪等排序方式。排序只改變顯示順序，不會改變玩家資格、遊戲規則或遊戲幣別。

若玩家認為排序結果不正確，客服應先確認：

- 玩家選擇的排序條件。
- 是否同時套用了分類或供應商篩選。
- 遊戲是否在正式 catalog 中標示為熱門或最新。

> - 狀態：待補正式產品截圖。

### 4.5 最近遊玩

- 最近遊玩代表玩家自己的遊玩清單，不等同於遊戲投注明細。
- 正式目標上限為最近 12 款遊戲。
- 最近遊玩清單只應顯示玩家曾經進入或成功啟動的遊戲；精確記錄時機需依正式 API 契約確認。
- 最近遊玩清單不等同於他人玩家資料卡上的最近遊玩，也不等同於會員中心的遊戲投注紀錄。
- 玩家更換裝置後是否同步，以正式後端保存方式為準。

## 5. 查看遊戲卡片與遊戲詳情

### 5.1 遊戲卡片

- 遊戲圖片或預設圖示。
- 遊戲名稱。
- 遊戲簡介。
- 遊戲標籤。

### 5.3 RTP 的客服說明方式

RTP 是遊戲在長期大量樣本下的理論回報率，不是單局、單日或個別玩家的保證回報，也不是玩家一定可以獲得的返還比例。

客服不得使用以下說法：

- 「RTP 高就一定會贏。」
- 「達到 RTP 數字就會補回本金。」
- 「這款遊戲保證中獎。」
- 「客服可以調整遊戲結果。」

若玩家詢問實際一局的輸贏，應以遊戲投注明細、遊戲供應商紀錄與正式結算結果為準，而不是用 RTP 反推單局結果。

>
> - 放置位置：本節 RTP 說明之後。
> - 用途：確認 RTP 顯示位置、文字定義與避免被誤解為保證回報的提示方式。
> - 狀態：待補正式產品截圖。

### 5.4 遊戲規則與實際結果

- 遊戲規則應以遊戲詳情、遊戲內說明與正式供應商規則為準。
- 遊戲卡片簡介不能取代完整遊戲規則。
- 顯示的最大倍數是規則資訊，不代表玩家一定能達到該倍數。
- 若網站簡介與遊戲內規則不一致，客服應保留兩邊畫面並升級產品或供應商確認，不自行選擇對玩家承諾。

## 6. 真錢遊玩啟動流程

本節描述進入真錢遊玩時的標準入口。真錢與試玩的完整差異請參考第四章。

### 6.1 未登入玩家

1. 玩家在遊戲卡片按下「真錢玩」。
2. 系統判斷玩家尚未登入。
3. 系統開啟登入視窗。
4. 玩家完成登入或註冊。
5. 系統返回原本選擇的遊戲或大廳。
6. 系統再次確認玩家是否仍可啟動該遊戲。
7. 符合條件時進入錢包選擇流程。

> **截圖預留｜03-6.1-01｜未登入玩家的真錢登入導引**
>
> - 放置位置：本節流程之後。
> - 用途：確認點擊真錢玩後的登入／註冊彈窗、原遊戲記憶與返回大廳 fallback。
> - 狀態：待補正式產品截圖。

### 6.2 已登入玩家

1. 玩家在遊戲卡片按下「真錢玩」。
2. 系統確認登入狀態仍有效。
3. 系統取得遊戲目前狀態與玩家可使用資格。
4. 系統顯示遊戲啟動視窗。
5. 玩家確認遊戲名稱、供應商與 RTP 等資訊。
6. 玩家從可用錢包中選擇本次遊戲使用的幣別來源。
7. 玩家按下「進入遊戲」。
8. 系統向正式遊戲啟動服務請求一次性遊戲網址或啟動 token。
9. 啟動成功後進入遊戲畫面。

> **截圖預留｜03-6.2-01｜已登入玩家的真錢啟動視窗**
>
> - 放置位置：本節流程之後。
> - 用途：確認遊戲狀態、玩家資格、遊戲資訊與進入遊戲按鈕在啟動前的呈現。
> - 狀態：待補正式產品截圖。

### 6.3 遊戲啟動時的錢包選擇

正式單一錢包架構下，遊戲不會建立獨立的遊戲子錢包，也不會要求玩家先把餘額轉入遊戲再轉出。啟動時選擇的 wallet，代表本次遊戲 session 從哪一個幣別／來源 bucket 扣款，不是玩家之間的轉帳，也不是外部提款。

目前正式模型包含以下遊戲錢包選項：

| 選項 | 說明 |
|---|---|
| 儲值金幣 | 儲值來源的金幣餘額。 |
| 活動金幣 | 活動或獎勵卡來源的金幣餘額。 |
| 儲值銀幣 | 儲值來源的銀幣餘額。 |
| 活動銀幣 | 活動或獎勵卡來源的銀幣餘額。 |
| 銅幣 | 試玩用途的銅幣來源；價值與可用範圍依第四章及第五章說明。 |

玩家看到的實際選項，應由正式遊戲支援幣別、玩家帳號狀態與餘額共同決定；不是每款遊戲一定會顯示所有選項。

## 7. 遊戲進行中的操作

正式單一錢包架構下：

- 遊戲供應商的下注與中獎結果會即時與平台錢包服務交換。
- 玩家不需要在官網與遊戲之間手動轉入或轉出遊戲餘額。
- 每筆下注、派彩與餘額變化應以正式錢包交易紀錄及遊戲投注明細為準。
- 若遊戲畫面與錢包餘額顯示不同，不應用畫面暫時顯示的數字直接判定最終結果。

### 7.4 返回大廳

## 10. 遊戲中斷與交易爭議處理

玩家反映「遊戲斷線、扣款不明、派彩未入帳或不知道該局結果」時，客服不得只依玩家截圖判定結果，也不得要求玩家重複下注驗證。

### 10.1 客服應先收集的資料

- 玩家帳號或玩家識別資訊。
- 遊戲名稱與供應商。
- 遊玩模式：試玩或真錢。
- 使用的錢包與幣別來源（若玩家看得到）。
- 發生時間與時區。
- 下注金額或玩家認知中的異動金額。
- 遊戲局號、交易編號或畫面顯示的識別碼。
- 斷線前最後一個操作。
- 是否重新登入、重新整理或再次進入遊戲。
- 錯誤訊息、遊戲畫面與交易紀錄截圖。

### 10.2 客服處理順序

1. 先請玩家停止重複下注或重複點擊進入遊戲。
2. 確認玩家是否仍可正常登入與進入其他功能。
3. 確認是否有全站或單一遊戲維護公告。
4. 取得遊戲投注明細與錢包交易紀錄所需資訊。
5. 判斷是啟動問題、遊戲載入問題、下注問題、派彩問題或顯示延遲。
6. 依案件類型升級給客服、技術、錢包或遊戲供應商負責單位。
7. 在正式結果確認前，不承諾退款、補發、取消或勝負結果。

> **截圖預留｜03-10-01｜遊戲紀錄與錢包交易查詢畫面**
>
> - 放置位置：本節客服處理順序之後。
> - 用途：確認客服／玩家需要比對的遊戲局號、BET／WIN、交易狀態與餘額紀錄欄位。
> - 狀態：待補正式產品截圖；若玩家端無此畫面，改放內部查詢畫面或標記為不提供玩家查看。
> - 注意：截圖不得包含其他玩家資料、完整 token、密碼或驗證碼。

## 11. 客服檢查清單

處理遊戲大廳或遊戲啟動問題時，客服依序確認：

1. 玩家是否完成必要的年齡確認。
2. 玩家是否已登入，登入狀態是否仍有效。
3. 問題發生在搜尋、卡片、啟動視窗、遊戲載入或遊戲進行中哪一階段。
4. 遊戲名稱、遊戲 key（若畫面可取得）與供應商。
5. 玩家選擇的是試玩或真錢模式。
6. 真錢模式下使用的錢包與幣別。
7. 是否有維護、VIP、幣別不支援或餘額不足提示。
8. 發生時間、時區與是否可重現。
9. 裝置、瀏覽器、網路與是否使用全螢幕。
10. 是否涉及實際下注、扣款、派彩或餘額異動。
11. 是否已有交易編號、局號或遊戲紀錄。

客服不得要求：

- 玩家提供完整遊戲啟動網址或 token。
- 玩家提供帳號密碼或驗證碼。
- 玩家為了測試而重複下注。
- 玩家自行修改瀏覽器或本機資料來繞過資格檢查。

## 12. 升級條件

符合以下任一情況，應建立客服案件或升級給產品、技術、錢包或遊戲供應商團隊：

- 正式 catalog 應存在的遊戲長時間無法搜尋或消失。
- 遊戲狀態顯示可遊玩，但所有玩家都無法啟動。
- 遊戲維護訊息與正式公告不一致。
- 玩家符合 VIP、幣別與餘額條件，仍被錯誤阻止進入。
- 遊戲啟動成功但畫面空白、session 無效或立即被踢出。
- 遊戲中途斷線後出現扣款、派彩或餘額不一致。
- 玩家不確定下注是否成立，且已有實際金額變動。
- 遊戲規則、RTP、最大倍數或賠付資料與正式公告不一致。
- 多款遊戲或多位玩家同時間發生同一啟動問題。
- 遊戲供應商回傳維護、簽章、商戶停用或系統繁忙等錯誤。
- 玩家要求客服繞過 VIP、幣別、年齡或餘額限制。

升級時至少附上：玩家識別資訊、遊戲名稱與供應商、模式、錢包幣別、發生時間、錯誤訊息、操作步驟、裝置瀏覽器、是否可重現、交易或局號資訊，以及是否有實際金額異動。不得附上密碼、驗證碼或完整啟動 token。

## 13. 客服回覆範例

### 13.1 找不到遊戲

> 請先清除搜尋文字，確認分類與供應商篩選是否已套用，再重新搜尋遊戲名稱。若仍找不到，請提供遊戲名稱與發生時間，我們會協助確認目前是否仍在正式上架清單中。

### 13.2 未登入無法真錢遊玩

> 真錢遊玩需要先登入會員帳號。請先完成登入，登入成功後回到遊戲大廳重新選擇該遊戲；如果登入後沒有回到原本的遊戲，請再次搜尋遊戲即可。

### 13.3 遊戲無法啟動

> 請提供遊戲名稱、供應商、發生時間、使用的模式，以及畫面顯示的錯誤訊息。若畫面涉及實際下注或餘額異動，請先不要重複點擊或再次下注，我們會先確認遊戲與交易紀錄。

### 13.4 RTP 說明

> RTP 是遊戲在長期大量樣本下的理論回報率，不代表單局或個別玩家一定會獲得相同回報，也不代表保證獲利。實際每局結果仍以遊戲規則與正式結算紀錄為準。

### 13.5 遊戲中斷或扣款疑問

> 請先不要重複下注或連續重新進入遊戲。請提供遊戲名稱、發生時間、下注金額、畫面錯誤訊息，以及可以提供的局號或交易編號，我們會依遊戲與錢包紀錄確認實際狀態。

### 13.6 VIP 或幣別限制

> 目前這款遊戲可能有 VIP 等級或可用幣別限制。請提供畫面顯示的提示與您選擇的幣別，我們會依正式遊戲資格與支援範圍協助確認，無法以人工方式繞過限制。

## 14. 目前系統差異（僅供內部參考）

以下內容不是正式產品說法：

- 目前前端遊戲 catalog 同時存在兩份資料來源，遊戲數量與分類尚未收斂；正式版本應改由單一 catalog API 提供。
- 目前遊戲畫面使用 `example.com` iframe 作為佔位內容，不代表正式遊戲供應商啟動網址。
- 目前前端遊戲啟動流程是本地狀態切換，尚未真正呼叫一次性遊戲 URL／launch token API。
- 目前前端遊戲啟動視窗會列出多種錢包，但尚未完整檢查遊戲維護、最低 VIP、支援幣別與最低進場金額。
- 目前前端選擇真錢遊玩後會顯示錢包選項，但不能把畫面上的餘額或測試資料視為正式帳務結果。
- 目前前端最近遊玩清單使用瀏覽器 localStorage，且可能在點擊遊戲卡片時就記錄，不代表正式後端的成功啟動紀錄。
- 目前前端的座位選擇元件存在但沒有接入正式遊戲流程，不應對玩家承諾目前一定可以選座位或機台。
- 目前前端沒有完整的遊戲維護、VIP 門檻、幣別支援與餘額不足提示；正式產品應由後端判定並回傳原因。
- 目前遊戲規則、描述與 RTP 等資料部分為示意內容，正式說法應以正式 catalog、CMS 與供應商規則為準。
