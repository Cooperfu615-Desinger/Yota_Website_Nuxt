# 第十章：獎勵卡與獎勵兌換

- 章節狀態：草稿，待產品確認
- 版本：0.1
- 建立日期：2026-08-01
- 適用對象：產品營運人員、客服人員
- 對應功能：獎勵卡列表、活動資產、卡片啟用、停用、刪除、流水進度、轉換、轉換通知、卡片過期
- 相關章節：第五章「錢包與遊戲幣別」、第九章「每日任務、活動與排行榜」、第十一章「站內信與系統通知」

> 目前官網路由名稱可能仍使用 `/lobby/gifts`，但本章的「獎勵卡」不是第八章的玩家贈禮。第八章是玩家與玩家之間的贈禮申請；第十章是活動獎勵資產的卡片管理與兌換。

## 1. 本章目的

本章說明玩家取得活動獎勵卡後，如何查看卡片、啟用或停用、查看活動幣與流水進度，以及在達成條件後如何轉換成儲值錢包資產。同時說明卡片過期、刪除、同幣別 active 限制與系統回收等情況。

客服閱讀本章後，應能回答以下問題：

- 活動金幣、活動銀幣為什麼一定會以獎勵卡呈現？
- 獎勵卡要不要先啟用才能使用？
- 同一幣別有多張卡時，哪一張會進入活動錢包？
- 流水目標、目前餘額、轉換上限與回收金額怎麼看？
- 達成流水後，活動幣如何轉成儲值金幣或儲值銀幣？
- 獎勵卡過期後餘額去哪裡？能否恢復？
- 玩家看不到新卡或轉換通知時，客服應查什麼？

本章的核心原則是：

> 所有活動金幣與活動銀幣都以獎勵卡為載體。獎勵卡自帶幣別、金額、流水目標、轉換上限、有效期限、來源與狀態；活動資產不能脫離卡片規則單獨解釋。卡片過期後餘額無法使用或取出，依正式規則沒收並記錄為 `WIPE`。

## 2. 獎勵卡與其他獎勵的區分

| 類型 | 內容 | 主要位置 | 可否直接視為儲值資產 |
|---|---|---|---|
| 每日金幣獎勵 | 儲值金幣入帳或待領金幣 | 錢包／交易紀錄 | 依正式發放結果 |
| 銅幣獎勵 | 無價值試玩幣 | 銅幣餘額 | 不可 |
| 活動金幣 | 以活動金幣獎勵卡承載 | 獎勵卡頁 | 不可直接等同儲值金幣 |
| 活動銀幣 | 以活動銀幣獎勵卡承載 | 獎勵卡頁 | 不可直接等同儲值銀幣 |
| 信箱儲值附件 | 儲值金、銀或銅幣等結構化附件 | 站內信 | 依領取後的幣別入帳 |
| 玩家贈禮 | 另一位玩家發出的贈禮申請 | 贈禮頁／保險箱 | 不屬於獎勵卡 |

活動金幣與活動銀幣不經站內信附件直接派發；若活動或補償需要發放活動幣，應建立獎勵卡，玩家透過獎勵卡頁查看新卡提示。

## 3. 獎勵卡正式資料

每張正式獎勵卡應由後端提供完整參數：

| 欄位 | 說明 |
|---|---|
| `currency` | `activity-gold` 或 `activity-silver`。 |
| `amount` | 卡片原始面額。 |
| `current_balance` | 卡片目前尚未使用或轉換的餘額。 |
| `turnover_target` | 完成轉換所需的有效流水目標。 |
| `turnover_progress` | 後端認列的有效流水進度。 |
| `conversion_limit` | 完成條件後最多可轉入儲值錢包的數量。 |
| `expires_at` | 卡片有效期限。 |
| `source` | 例如每日簽到里程碑或營運補償。 |
| `status` | 未啟用、使用中、暫停、已轉換或已過期等狀態。 |
| `id` | 卡片唯一識別碼，供客服與正式流水查詢。 |

卡片總數目前暫定不設上限，但同一幣別同時只能有一張 `active` 卡。排序與篩選方式仍待產品確認，不可由固定展示順序推論卡片優先級。

## 4. 取得獎勵卡

### 4.1 每日簽到里程碑

1. 玩家依第九章完成每日簽到。
2. 累積天數達到第 15 天或第 20 天里程碑。
3. 玩家在每日任務頁點擊里程碑領取。
4. 系統建立對應的活動銀幣或活動金幣獎勵卡。
5. 玩家前往獎勵卡頁查看卡片。
6. 玩家依卡片狀態決定是否啟用。

里程碑已達成但尚未點擊領取時，不代表卡片已經建立；客服需分辨「已達成」、「已領取里程碑」與「卡片已出現在獎勵卡列表」三個狀態。

### 4.2 營運補償或活動派發

正式產品若因活動、服務異常或其他規則派發活動金幣／銀幣，應建立具有完整參數的獎勵卡。玩家可以透過獎勵卡未讀提示或獎勵卡列表查看，不應期待在站內信附件或主錢包儲值欄位直接看到活動幣。

客服處理補償問題時，不需要操作營運後台；應確認玩家帳號、卡片 ID、卡片來源與狀態，再依案件流程升級查詢。

## 5. 查看獎勵卡流程

1. 玩家登入官網。
2. 進入「獎勵卡」頁面。
3. 查看活動金幣與活動銀幣總額。
4. 查看每張卡片的來源、原始面額、目前餘額、流水進度、轉換上限與期限。
5. 查看卡片狀態與可用操作。
6. 若有新卡未讀提示，開啟新卡明細確認來源與規則。
7. 若卡片已完成轉換，查看轉換通知與儲值錢包交易紀錄。

活動資產總額可包含 active 與 paused 卡的卡片餘額；但可供遊戲使用的活動餘額，應依遊戲啟動時可用 bucket、卡片狀態與遊戲資格判定。客服不能看到活動總額後，就直接說全部都可以下注。

## 6. 卡片狀態與操作

### 6.1 狀態定義

| 狀態 | 說明 | 可否遊戲使用 | 可否刪除 |
|---|---|---|---|
| `INACTIVE` | 卡片已取得但尚未啟用 | 否 | 依正式刪除規則 |
| `ACTIVE` | 卡片正在提供對應活動幣額度 | 依遊戲支援與資格 | 不可直接刪除 |
| `PAUSED` | 卡片暫停使用，餘額保留 | 通常不可作為目前扣款來源 | 依正式刪除規則 |
| `CONVERTED` | 已完成轉換，卡片不再提供活動額度 | 否 | 依正式保留規則 |
| `EXPIRED` | 到期失效，餘額無法使用或取出 | 否 | 依正式紀錄保留規則 |

正式 API 狀態名稱可能使用小寫或其他顯示文字，客服應以後端契約與畫面文案對照；不要把 `PAUSED` 說成餘額消失，也不要把 `EXPIRED` 說成玩家自行刪除。

### 6.2 啟用卡片

1. 玩家開啟一張 `INACTIVE` 或 `PAUSED` 卡片。
2. 查看幣別、面額、流水、上限與期限。
3. 按下「啟用」。
4. 系統確認卡片仍有效，且同幣別 active 卡的規則可被處理。
5. 若同幣別已有另一張 active 卡，原 active 卡轉為 paused。
6. 目前卡片轉為 active。
7. active 卡的可用餘額依遊戲資格與 wallet 選項提供。

啟用不是把活動幣轉成儲值幣，也不是消耗卡片餘額；它只是決定哪一張同幣別卡可以作為目前活動資產來源。

### 6.3 停用卡片

1. 玩家選擇目前 active 卡。
2. 查看停用提示。
3. 按下「停用」。
4. 系統將卡片轉為 paused，並保留卡片餘額、流水與期限。
5. 玩家若要繼續使用，之後可以重新啟用。

停用不等於轉換、退款或刪除，也不會把卡片餘額轉入儲值錢包。

### 6.4 刪除卡片

目前畫面僅允許非 active 卡進入刪除確認。正式版本若保留刪除功能，應在確認畫面清楚說明：

- 刪除後卡片是否仍可在歷史紀錄查詢。
- 未用餘額是否會失效或被回收。
- 是否可以重新取得同一張卡。
- 已轉換或已過期卡片是否允許刪除。

在上述規則未完全確認前，客服不可承諾刪除後可以恢復，也不可引導玩家用刪除方式解決卡片顯示問題。若卡片餘額、狀態或刪除結果不一致，應先查正式卡片紀錄再處理。

## 7. 流水進度規則

### 7.1 流水不是卡片面額

- 卡片面額是活動資產數量。
- 流水目標是玩家需要完成的有效遊戲活動量。
- 目前餘額可能因下注、派彩或其他正式遊戲結算而變動。
- 轉換上限是完成條件後最多可以轉成儲值幣的數量，不等於目前可用餘額。
- 活動金幣／銀幣的有效流水不能由客服以玩家總下注額直接推算。

### 7.2 有效流水由後端認列

正式版本應由後端依錢包、遊戲供應商與交易規則累積流水。`BET` 不一定等於有效流水；取消、退款、回滾、無效局、維護測試或不符合活動條件的遊戲，可能不被計入。

前台只應顯示後端提供的流水進度與剩餘目標。客服不得教玩家透過重複點擊、測試按鈕或特定非正式操作「刷滿流水」。

### 7.3 查看流水

1. 玩家開啟獎勵卡。
2. 查看目前流水與流水目標。
3. 若有明細入口，查看可認列的遊戲交易、時間與剩餘目標。
4. 查看卡片是否仍 active、是否已暫停或已過期。
5. 若達成流水，等待系統依正式規則完成轉換或顯示可轉換通知。

## 8. 獎勵卡轉換流程

### 8.1 達成條件後

1. 後端確認卡片有效流水已達 `turnover_target`。
2. 系統依正式轉換規則計算可轉換數量。
3. 轉換數量為 `min(卡片目前餘額, conversion_limit)`。
4. 超過轉換上限的部分記為系統回收 `recovered`。
5. 活動金幣轉入儲值金幣；活動銀幣轉入儲值銀幣。
6. 卡片狀態變更為 `CONVERTED`，卡片活動餘額歸零。
7. 系統建立 `BONUS_CONVERT`／正式對應的資產流水。
8. 玩家收到轉換完成通知，並可在錢包與交易紀錄確認。

實際是自動轉換、由玩家按下確認，或由後端完成後前台通知，需以正式 API 契約確認；客服不得要求玩家透過測試按鈕觸發轉換。

### 8.2 轉換範例

假設：

- 活動金幣卡目前餘額為 12,000。
- 轉換上限為 10,000。
- 流水已達成。

則：

- 儲值金幣入帳 10,000。
- 系統回收 2,000。
- 活動金幣卡轉為已轉換。
- 12,000 不能全部轉成儲值金幣，因為卡片轉換上限是 10,000。

客服需向玩家說明「未轉換部分是依卡片上限回收」，不能說成系統漏發或提款失敗，除非正式流水與卡片參數不一致。

## 9. 過期規則

- 後台可設定每張卡的有效期限。
- 到期後由後端排程或正式讀取流程判定卡片失效。
- 卡片狀態變更為 `EXPIRED`。
- 卡片內剩餘餘額無法使用，也無法取出或轉換。
- 沒收資產以 `WIPE`／`BONUS_WIPE` 方向記錄。
- 若過期前卡片是 active，玩家活動錢包總額可能下降，前台應顯示原因。
- 客服不得以目前顯示的日期、瀏覽器時間或畫面未更新，直接判定卡片是否過期。

過期不是玩家按下停用，也不是一般刪除；它是正式時間規則觸發的終結狀態。除非正式資料有誤，過期餘額不應承諾恢復。

## 10. 常見情境與處理矩陣

| 玩家情況 | 玩家可能看到的結果 | 客服第一步 | 後續處理 |
|---|---|---|---|
| 完成第 15／20 天但沒有卡片 | 里程碑尚未領取或卡片資料延遲 | 查里程碑領取狀態與卡片清單 | 依狀態補查，不直接補發活動幣 |
| 卡片顯示未啟用 | 活動總額存在，但遊戲選項不可用 | 引導玩家查看卡片規則並啟用 | 確認遊戲是否支援活動幣 |
| 啟用一張後另一張變停用 | 同幣別只能一張 active | 說明另一張轉為 paused、餘額保留 | 不視為餘額遺失 |
| 玩家停用卡片後想繼續遊戲 | 活動餘額不在可用選項 | 引導重新啟用有效卡片 | 查卡片是否已過期或轉換 |
| active 卡無法刪除 | 刪除按鈕停用 | 說明需先依正式規則停用 | 不引導用其他方式刪除 |
| 流水沒有增加 | 遊戲已下注，但活動卡進度不變 | 查遊戲、卡片狀態與有效流水規則 | `BET` 不一定等於有效流水，必要時升級 |
| 流水突然減少 | 交易取消、退款或回滾 | 查後端流水明細與交易狀態 | 依正式回滾規則說明，不人工補流水 |
| 已達流水但沒有轉換 | 轉換仍處理中或條件未被後端確認 | 查卡片狀態與 `BONUS_CONVERT` | 若條件已達仍無流水，升級 |
| 轉換後收到較少 | 超過 conversion limit 被回收 | 比對餘額、轉換上限與回收數量 | 計算正確則說明上限 |
| 卡片逾期餘額消失 | `EXPIRED`／`WIPE` | 查卡片期限、server 時間與流水 | 規則正確時說明沒收，不承諾恢復 |
| 未到期卻顯示過期 | 前端日期或後端判定異常 | 記錄卡片 ID、期限與時間 | 交由技術查後端狀態 |
| 活動幣找不到主錢包 | 玩家只查看儲值金幣／銀幣 | 引導獎勵卡頁與遊戲來源選項 | 活動幣不等同儲值幣 |
| 新卡沒有提示 | 卡片已建立但未讀通知未顯示 | 查 `/reward-cards/unread` 與卡片清單 | 提示缺失升級，不視為卡片未發放 |
| 玩家要求把活動幣直接換現金 | 詢問提款或兌現 | 說明活動卡只能依正式轉換規則入儲值錢包 | 平台不提供外部提款或現金兌換 |
| 玩家要求客服直接完成轉換 | 想跳過流水條件 | 說明只能依後端正式流水與規則 | 不人工修改卡片狀態 |

## 11. 客服檢查清單

1. 玩家帳號與身分驗證。
2. 獎勵卡 ID、來源與建立時間。
3. 卡片幣別、原始面額與目前餘額。
4. 卡片狀態、active／paused 同幣別卡狀況。
5. 流水目標、後端認列進度與剩餘流水。
6. 轉換上限、預計轉換數量與回收數量。
7. 有效期限、伺服器時間與是否有 `EXPIRED`／`WIPE` 流水。
8. 是否已建立 `BONUS_CONVERT` 與儲值錢包入帳紀錄。
9. 新卡提示或轉換通知是否已讀。
10. 玩家進入的是獎勵卡頁、錢包頁、遊戲頁或站內信。

## 12. 客服可直接處理與升級條件

### 12.1 可直接處理

- 說明活動幣一定以獎勵卡為載體。
- 引導玩家查看卡片參數、狀態與有效期限。
- 說明啟用、停用與同幣別單一 active 的關係。
- 說明流水目標、轉換上限與回收金額的差異。
- 說明轉換後活動幣進入對應儲值金幣／銀幣錢包。
- 說明卡片過期後無法使用或取出，並引導查詢正式狀態。

### 12.2 必須升級

- 卡片已達流水但沒有轉換、通知或儲值入帳。
- 卡片未到期卻被標記 `EXPIRED` 或產生 `WIPE`。
- 卡片狀態、活動餘額與遊戲可用選項互相矛盾。
- 有效流水與遊戲、下注、退款或回滾紀錄不一致。
- 轉換上限、回收數量或入帳數量計算錯誤。
- 新卡已存在但未讀提示、卡片清單或補償來源缺失。
- 同一張卡重複轉換或同一轉換重複入帳。

### 12.3 禁止事項

- 不得把活動幣說成儲值金幣或可直接提款的現金。
- 不得用前端測試按鈕、手動改狀態或人工加流水處理玩家案件。
- 不得承諾卡片過期後一定可以恢復。
- 不得把轉換上限以上的回收數量說成系統少發。
- 不得要求玩家提供密碼、驗證碼或支付資料。
- 不得把第八章玩家贈禮與本章獎勵卡混稱為同一項功能。

## 13. 客服回覆範例

### 玩家詢問「活動金幣為什麼不在錢包？」

> 活動金幣與活動銀幣會以獎勵卡形式提供，不一定會直接顯示在儲值金幣或儲值銀幣欄位。請到獎勵卡頁查看卡片是否已領取、是否啟用，以及目前的流水與有效期限。

### 玩家詢問「我已經下注，為什麼流水沒有增加？」

> 有效流水會依獎勵卡、遊戲與正式交易規則由系統認列，並不是每一筆下注都一定會計入。請提供獎勵卡 ID、遊戲名稱、操作時間與相關局號，我們會核對正式流水明細；請不要透過重複操作或測試按鈕嘗試增加流水。

### 玩家詢問「為什麼只能轉換 10,000？」

> 這張獎勵卡的轉換上限是 10,000。完成流水後，最多只能將上限內的餘額轉入對應儲值錢包，超過上限的部分會依卡片規則回收。請以卡片明細顯示的原始餘額、轉換上限與回收數量為準。

### 玩家詢問「獎勵卡過期後可以補回嗎？」

> 獎勵卡到期後會依正式規則失效，卡內餘額無法使用或取出，並會留下回收紀錄。請提供卡片 ID 與畫面顯示的期限，我們會先確認伺服器時間與卡片狀態；若正式資料判定有誤，再交由相關團隊查核。

## 14. 目前系統差異

以下只供內部理解前端 Mock，不可取代正式規則：

- 目前獎勵卡來源、卡片定義與部分參數寫在前端 composable；正式版本應由 `/reward-cards` 回傳每張卡的完整資料。
- 目前前端只建立每日簽到第 15／20 天的測試卡，正式卡片數量暫定不設上限，且也可能來自營運補償。
- 目前流水可透過遊戲畫面的測試按鈕直接完成，正式流水必須由後端依 Provider 交易規則認列。
- 目前狀態 enum 尚未包含正式的 `EXPIRED`；正式版本需由後端判定過期並以 `WIPE` 記帳。
- 目前前端刷新後獎勵卡狀態可能回到空白，正式版本應由後端保存並跨裝置同步。
- 目前部分規則說明 Modal 仍顯示「待補充」，不可直接當作正式客服話術。
- 目前獎勵卡頁沒有完整的新增卡未讀提示與流水明細 API，正式版本應補上。
