# 第十三章：客服問題回報與案件處理

- 章節狀態：草稿，待產品確認
- 版本：0.1
- 建立日期：2026-08-01
- 適用對象：產品營運人員、客服人員
- 對應功能：客服 FAQ、客服頻道、問題分類、客服案件、案件訊息、已讀狀態、玩家檢舉
- 相關章節：第二章「忘記密碼與帳號恢復」、第六章「儲值與付款」、第十二章「好友、聊天、封鎖與檢舉」、第十五章「客服回覆話術與快速查詢表」

## 1. 本章目的

本章說明玩家如何從官網尋找常見問題、建立客服案件、補充案件內容、查看客服回覆，以及客服人員如何判斷案件類型、收集必要資料、回覆玩家與進行升級。

本章不描述營運後台的案件分派、客服權限、人工修改資料或案件報表操作。若需要後台操作，應使用另行製作的營運後台手冊。

客服閱讀本章後，應能回答：

- 什麼情況適合先看 FAQ，什麼情況需要建立客服案件？
- 玩家可以選擇哪些問題分類？
- 一位玩家同時可以有幾件進行中的案件？
- 案件建立、回覆、已讀與結案後，各階段的操作方式是什麼？
- 儲值、遊戲結算、帳號安全、檢舉與一般詢問，各需要哪些資料？
- 什麼資料可以請玩家提供，什麼資料絕對不能索取？
- 何時需要升級給技術、金流、遊戲供應商或安全審核單位？

## 2. 客服入口與功能區分

### 2.1 FAQ 與客服案件的差異

| 功能 | 用途 | 是否產生個人案件 | 適用情況 |
|---|---|---:|---|
| FAQ／支援頁 | 提供通用說明與操作指引 | 否 | 玩家想先自行排除問題 |
| 客服頻道 | 查看案件、建立案件、接收回覆 | 是 | 問題與個人帳號、訂單或案件狀態有關 |
| 玩家檢舉 | 回報其他玩家的不當行為 | 目前可能建立客服案件；正式獨立案件模型待確認 | 騷擾、詐騙、冒用身分或違規行為 |
| 外部官方客服管道 | 依正式公告提供補充聯繫 | 依該管道規則 | 官網無法登入或產品另行指定的安全事件 |

FAQ 的內容可以直接套用到相同條件的玩家；客服案件則必須依玩家帳號、時間、訂單或遊戲紀錄個別判斷。不能用 FAQ 的一般說明取代對個人交易或帳號案件的查核。

### 2.2 進入客服頻道

1. 玩家登入官網。
2. 從會員中心、聊天頁或支援頁進入客服入口。
3. 選擇「客服」或「客服頻道」。
4. 查看進行中的案件、已結案案件與未讀回覆。
5. 若沒有適合的進行中案件，選擇「新增問題」建立案件。

若玩家未登入，客服頁可以提供一般 FAQ，但涉及個人帳號、訂單、資產或案件狀態的功能應先要求登入或改走正式身分驗證流程。

## 3. 問題分類

目前前台客服分類如下。客服建立案件時，應選擇最接近實際問題的分類；若問題跨越多個功能，使用最主要的結果作為主分類，並在第一則訊息補充其他關聯資訊。

| 分類 | 適用問題 | 不應混用的情況 |
|---|---|---|
| 帳號問題 | 登入、註冊、帳號狀態、個人資料 | 純粹忘記密碼先看第二章；若仍無法恢復再建立案件 |
| 儲值／付款 | 儲值未入帳、支付失敗、付款頁錯誤 | 不把玩家對玩家贈禮當成儲值 |
| 帳務／訂單 | 訂單查詢、重複扣款、金額或交易狀態 | 遊戲結算問題應選遊戲／結算 |
| 遊戲／結算 | 遊戲無法啟動、遊戲結果、下注或結算異常 | 若只是進入大廳或登入問題，應選帳號或一般遊戲入口問題 |
| 活動／獎勵 | 每日任務、活動資格、排行榜、獎勵卡 | 站內信收件問題需補充信件或獎勵識別資訊 |
| 保險箱／贈禮 | 金庫、幣別兌換、轉移、贈禮申請 | 儲值付款問題不要只選保險箱 |
| 檢舉玩家 | 騷擾、不當言論、詐騙、冒用身份 | 單純不想聯絡對方可先封鎖；有違規內容再檢舉 |

分類名稱、分類 code 與後端對應應以正式 API 契約為準。客服在回覆中可使用玩家看得到的中文名稱，不應把內部 code 當成玩家必須理解的術語。

## 4. 正式產品規則

### 4.1 建立案件

- 建立案件需要登入會員。
- 玩家必須選擇一個問題分類。
- 第一則說明不可為空白或只有空格。
- 同一位玩家同時最多只能有一件進行中的客服案件。
- 案件建立成功後，系統應回傳案件識別資訊，玩家可在客服頻道追蹤。
- 未完成的草稿是否保存、是否可以附加檔案，待正式產品規則確認；客服不可承諾草稿一定會保存。

### 4.2 案件狀態

玩家端目前以兩種主要狀態理解：

| 玩家端狀態 | 意義 | 玩家可做的事 |
|---|---|---|
| 進行中 | 案件尚未結束，仍可與客服往來 | 查看內容、補充訊息、閱讀回覆 |
| 已結案 | 案件已停止處理 | 查看歷史內容；若有新問題，建立新的案件 |

後端可能使用未分派、待處理、處理中與已結案等較細的內部狀態。這些狀態如何映射到玩家端、是否顯示客服正在處理，仍以正式契約為準。客服不得把內部狀態名稱或其他玩家的案件資料告訴玩家。

### 4.3 案件訊息與已讀

- 進行中的案件可以追加訊息，但內容應集中於同一問題。
- 客服回覆後，玩家會看到未讀提示。
- 玩家打開案件或使用已讀操作後，未讀數應清除。
- 已結案案件不可繼續追加訊息；若前台提供重新開啟功能，須以正式規則為準，目前不可自行承諾。
- 不要用連續建立多件案件取代同一案件的補充訊息，這會造成案件分散與查核延遲。

### 4.4 檢舉案件

玩家可以從玩家卡進入檢舉流程。現行前端流程可能將檢舉內容建立在客服案件中；後端另有獨立 reports 介面的規劃，是否正式採用獨立檢舉案件、檢舉狀態與回覆方式仍待確認。

在正式規則未確認前，客服應採以下說法：

> 檢舉送出後會交由平台審核；玩家可依畫面提供的案件或回報識別資訊查詢自己的提交狀態。平台不會提供其他玩家的個人資料或內部處分細節。

## 5. 建立客服案件的標準流程

### 5.1 玩家操作流程

1. 玩家進入 FAQ 或客服頻道。
2. 先查看與問題相關的 FAQ，依步驟自行排除。
3. 若問題仍未解決，登入後進入客服頻道。
4. 確認是否已有同一問題的進行中案件。
5. 若有，開啟原案件並在同一案件補充資訊；若沒有，選擇「新增問題」。
6. 選擇問題分類。
7. 填寫第一則訊息，包含發生時間、操作流程、畫面結果與希望協助的內容。
8. 確認沒有放入密碼、驗證碼或完整付款敏感資料。
9. 送出案件。
10. 記下案件編號或保留成功畫面。
11. 回到客服頻道查看案件狀態與客服回覆。

### 5.2 客服回覆流程

1. 確認玩家身分與案件編號。
2. 閱讀分類、第一則訊息與既有往來內容。
3. 先判斷是否為安全、金流、遊戲結算或帳號存取的高風險案件。
4. 若資料不足，提出一次一組、清楚且不涉及敏感資訊的補充問題。
5. 若可直接排除，依對應章節提供操作步驟。
6. 若需要其他單位查核，說明已轉交的問題類型與玩家需要保留的資料；不提供未確認的處理時間。
7. 回覆完成後確認訊息內容、案件狀態與是否需要玩家下一步操作。
8. 玩家確認問題處理完成或依正式規則結案後，案件進入已結案狀態。

## 6. 各類案件應收集的資訊

### 6.1 帳號問題

請玩家提供：

- 帳號或玩家 ID（依身分驗證政策確認）。
- 發生時間與時區。
- 登入、註冊或恢復密碼的實際步驟。
- 畫面顯示的錯誤文字或錯誤代碼。
- 使用裝置、作業系統、瀏覽器與是否能重現。

不要要求：

- 完整密碼。
- 簡訊、Email 或雙重驗證的一次性驗證碼。
- 第三方登入密碼。

### 6.2 儲值／付款與帳務／訂單

請玩家提供：

- 玩家 ID 或已完成身分驗證的帳號資訊。
- 訂單編號、交易編號或支付平台提供的可公開識別碼。
- 儲值幣別、金額、建立時間與付款方式。
- 付款頁顯示的狀態，以及錢包目前顯示的結果。
- 必要時提供遮蔽敏感欄位的付款證明截圖。

客服應先區分「已扣款但未入帳」、「付款未完成」、「訂單處理中」、「重複扣款」與「玩家看錯幣別」。不要在未查核前直接承諾退款、補幣或再次付款。

不要要求完整卡號、卡片安全碼、網銀密碼、支付密碼或簡訊驗證碼。若玩家已經在聊天中貼出，應提醒立即刪除或遮蔽，並依公司資安流程處理。

### 6.3 遊戲／結算

請玩家提供：

- 遊戲名稱與遊戲模式：試玩或真錢。
- 發生時間與時區。
- 遊戲房間、局號、回合或交易識別資訊（若畫面提供）。
- 操作前後餘額或下注結果，但不要要求玩家提供帳戶密碼。
- 錯誤畫面、遊戲中斷位置與是否能重現。

遊戲結果、下注與結算涉及不可逆資料時，客服不可自行判定輸贏或承諾改判；應保留證據並升級遊戲／結算查核。

### 6.4 活動／獎勵與保險箱／贈禮

請玩家提供：

- 活動名稱、任務或排行榜名稱。
- 完成條件、完成時間與畫面顯示。
- 獎勵卡、站內信、贈禮申請或交易識別資訊。
- 幣別、數量、來源與目前顯示位置。
- 若是贈禮，提供寄件人／收件人玩家 ID、申請狀態與時間。

客服應先確認玩家查詢的是主錢包、活動幣、保險箱、獎勵卡或站內信附件，避免因資產位置不同而誤判為遺失。

### 6.5 檢舉玩家

請玩家提供被檢舉玩家 ID、發生時間、頻道、檢舉原因、原始內容、截圖與是否涉及付款或外部聯絡。檢舉詳情見第十二章。

## 7. 狀況與例外處理矩陣

| 狀況 | 玩家可能看到的結果 | 客服判斷 | 建議處理 |
|---|---|---|---|
| 未登入建立案件 | 被導向登入或無法送出 | 缺少會員身分 | 引導登入；若無法登入先看第二章並記錄登入錯誤 |
| 未選分類 | 送出按鈕停用或顯示錯誤 | 案件資料不完整 | 請玩家選擇最接近的分類 |
| 第一則訊息空白 | 顯示必填提示 | 不符合建立條件 | 請補充事件、時間與畫面結果 |
| 已有一件進行中案件 | 無法建立第二件 | 達到同時進行上限 | 引導開啟原案件補充，不要重複開案 |
| 案件送出成功但找不到 | 頁面未刷新或清單查詢失敗 | 可能是同步或載入問題 | 先記錄案件編號與時間，再重整；仍無法追蹤則升級 |
| 案件有未讀回覆 | 清單有未讀提示 | 需要玩家查看回覆 | 引導開啟案件並確認下一步 |
| 已結案仍想留言 | 輸入停用或送出失敗 | 案件不可追加 | 建立新案件並附上原案件編號 |
| 玩家連續建立多個案件 | 第二件被阻擋 | 已有進行中案件 | 合併資訊到原案件，避免重複建立 |
| 附件無法上傳 | 沒有附件入口或上傳失敗 | 附件規格尚待確認或網路問題 | 先請玩家以文字提供必要資訊；截圖需遮蔽敏感資料 |
| 玩家要求固定處理時間 | 希望得到保證 | 目前沒有可對外承諾的統一時限 | 說明已依案件類型轉交，完成後會以正式管道通知 |
| 儲值已扣款但餘額未變 | 付款成功、錢包未入帳 | 金流或帳務查核 | 先不要再次付款，收集訂單資料並升級 |
| 遊戲中斷且餘額異常 | 結果待確認 | 遊戲／結算高風險 | 保留局號與時間，不自行補扣或改判 |
| 檢舉重複送出 | 多筆案件或送出被阻擋 | 可能是重複回報 | 保留最新識別資訊，避免重複提交 |
| 無法查看其他玩家處分 | 沒有處分明細 | 涉及第三方隱私 | 只提供自己案件的提交狀態 |

## 8. 升級分類與優先判斷

### 8.1 立即依安全流程升級

- 玩家帳號疑似被盜、登入通知異常或個資外洩。
- 玩家收到冒充官方的付款要求、驗證碼要求或可疑連結。
- 付款資料、卡號、驗證碼或密碼疑似外洩。
- 重大詐騙、威脅、人身安全或大規模社群風險。

客服先提醒玩家停止付款、停止提供資料並保留證據，不要在案件訊息中要求玩家貼出更多敏感內容。

### 8.2 金流／帳務升級

- 支付端顯示成功但官網未入帳。
- 重複扣款、金額不符、訂單狀態與錢包狀態不一致。
- 需要退款、沖正或人工查核，但客服沒有授權處理。

### 8.3 遊戲／結算升級

- 遊戲結果、局號、下注或結算與玩家畫面不一致。
- 遊戲斷線、重連後結果不明或餘額異常。
- 多名玩家同時回報同一遊戲錯誤。

### 8.4 產品／技術升級

- 連續發生同一前端錯誤、按鈕無反應或資料消失。
- 案件、好友、封鎖、聊天室或未讀狀態跨頁不同步。
- 玩家可看到不應公開的資料或可繞過權限操作。

## 9. 客服回覆原則

每次回覆建議包含四段：

1. **確認現象**：重述玩家遇到的功能與結果，避免答非所問。
2. **判斷條件**：說明目前需要確認的是登入、資格、付款、狀態或系統錯誤。
3. **提供處理**：給出玩家下一步，不要一次要求無關資料。
4. **說明後續**：若需升級，說明案件已記錄的識別資訊、玩家應保留的資料與等待通知方式。

### 9.1 可直接使用的回覆

**已達進行中案件上限**

> 目前您的帳號已有一件進行中的客服案件。為避免資訊分散，請開啟原案件並在同一串訊息補充本次問題；若您提供原案件編號，我們也可以協助確認位置。

**案件已結案**

> 這件案件目前已結案，已無法在原案件追加訊息。若是新的問題，請重新建立案件；若與原案件相關，請在新案件中附上原案件編號與最新狀況。

**需要訂單資料**

> 為協助查詢，請提供訂單編號、付款時間、幣別與金額，以及付款頁顯示的狀態。請勿提供密碼、簡訊驗證碼、完整卡號或安全碼。

**需要遊戲資料**

> 請提供遊戲名稱、試玩或真錢模式、發生時間、局號或畫面上的交易識別資訊，以及錯誤畫面。請先不要重複下注或再次付款，我們會依資料進行查核。

**檢舉案件**

> 您提供的檢舉內容已記錄，平台會依規則與證據進行審核。為保護其他玩家的隱私，我們不會提供對方的內部處分細節；請保留案件編號，後續依正式通知查看自己的回報狀態。

## 10. 禁止事項

- 不得要求玩家提供完整密碼、一次性驗證碼、支付密碼、卡片安全碼或第三方帳密。
- 不得在沒有查核結果時承諾補幣、退款、改判遊戲結果、恢復帳號或解除處分。
- 不得為了繞過「同時一件進行中案件」而替玩家建立重複案件。
- 不得把客服案件編號、內部狀態、其他玩家資料或審核結果公開給無關人員。
- 不得使用「一定在幾分鐘內處理完成」等未經正式確認的時限話術。
- 不得要求玩家把完整付款證明、身分證件或私人聊天內容公開到世界頻道。
- 不得把檢舉案件當成一定處分的承諾，也不得鼓勵玩家重複檢舉。

## 11. 目前系統差異

以下內容只供內部理解前端 Mock，不可取代正式產品規則：

- 目前客服案件資料主要存在瀏覽工作階段，重新整理或重新進入可能回到測試資料；正式版本應由後端保存。
- 目前前台狀態主要顯示 `ongoing` 與 `closed`，後端更細的未分派、待處理與處理中狀態如何映射仍待確認。
- 目前第一則訊息送出後建立 session Mock 案件；正式版本應使用客服案件 API 並保存 server id。
- 目前客服回覆的即時更新預留 WebSocket／即時服務，尚不能將前端畫面出現的回覆當成正式案件回覆證明。
- 目前檢舉可能直接建立 `report` 類型客服案件；獨立 reports 服務是否為正式流程待確認。
- 公開支援頁部分文字包含官方外部管道、處理時間或服務承諾；在產品正式公告與 SLA 未確認前，不應直接引用為保證。

## 12. 待產品確認

- FAQ、客服頻道與外部官方客服的正式入口與登入條件。
- 進行中案件上限是否固定為一件，以及案件建立後是否可由玩家取消或重新開啟。
- 案件狀態在玩家端的正式名稱、顏色、通知方式與結案條件。
- 客服訊息字數、附件格式、附件大小與敏感內容掃描規則。
- 客服回覆是否支援 WebSocket、Email、站內通知或其他通知方式。
- 檢舉是否使用獨立 `/reports` 案件、檢舉理由 code、證據保存期限與玩家可見狀態。
- 重大安全、金流與遊戲結算案件的內部 SLA；未確認前不得填入固定時間。
- 玩家無法登入時的正式身分驗證與替代客服管道。
- 案件是否支援合併、轉分類、轉交與玩家重新開案。
