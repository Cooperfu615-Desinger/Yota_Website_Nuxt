## 1. 這個功能是什麼

本功能讓登入後玩家閱讀與發送世界訊息、查看在線玩家、發起私人對話、管理好友／黑名單、檢舉玩家，並在客服頻道建立與追蹤案件。玩家可從玩家小卡導向贈禮／轉帳或客服，但任何聊天操作都不能繞過財務、身份、年齡、內容安全與案件權限。

世界、私人與客服頻道需清楚呈現可見範圍、未讀、案件狀態、發送結果與失敗原因；目前頁面資料與送出結果不代表服務端已送達或已受理。

| 名詞 | 定義 |

## 5. 欄位說明

| 欄位 | 顯示／輸入內容 | 限制與目前狀態 |
|---|---|---|
| channel | `world`、`private`、`support` | query 只代表視圖，不代表權限 |
| player | 名稱、account／playerId、VIP、等級、在線狀態 | 只顯示授權的公開資料；正式由服務端判斷 |
| message | 世界／私人／客服訊息文字與時間 | 空訊息、敏感內容、長度與頻率限制需服務端重驗 |
| conversation | 對話 ID、對象、最後訊息、未讀 | 目前私人對話為頁面 Mock，重新整理不保證保存 |
| ticket | 案件 ID、類別、狀態、最後訊息、更新時間、未讀 | 目前同時最多 1 筆進行中案件；正式限制待確認 |
| report | 檢舉對象、原因、補充、時間與案件 reference | 無效對象、空原因或案件上限時不可建立半成品 |
| relation | 好友／封鎖／解除封鎖狀態 | 目前由 `useSocialState.ts` 保存本次瀏覽狀態 |

## 6. 狀態說明

| 狀態 | 目前／目標行為 |
|---|---|
| `connected`／`connecting`／`offline` | 世界／私人訊息需呈現連線、重連與不可發送原因 |
| `sending`／`sent`／`failed` | 發送結果要可辨識；頁面新增不等於服務端送達 |
| `unread`／`read` | 開啟對話或案件可更新未讀；正式需服務端游標 |
| `ongoing`／`closed` | 客服案件可對話／唯讀；結案案件不可再送訊息 |
| `blocked`／`not-eligible` | 玩家卡、私訊、贈禮與檢舉依權限顯示原因 |
| `empty`／`error`／`rate-limited` | 清單、頻道、案件與檢舉均需可重試或導流 |

目前世界／私人頻道為 seed data，客服案件由 `useSupportTicketState.ts` 模擬；正式服務需以 WebSocket／客服 API 為唯一來源。

## 7. 查詢、排序與分頁

- 客服案件需支援全部、進行中、已結案篩選，並定義更新時間排序、分頁／cursor 與未讀彙總。
- 私人對話需定義最近更新排序、歷史訊息載入、已讀游標與搜尋；目前只顯示頁面 Mock。
- 世界頻道需定義歷史訊息載入、訊息序號、玩家清單更新與內容查詢，不以一次 seed data 代表完整資料。
- 玩家清單、好友與黑名單需定義公開欄位、排序、空資料、權限與服務失敗狀態。

## 8. 操作與跳轉

### 8.1 世界與私人頻道

玩家進入聊天頁後可閱讀世界訊息、輸入並送出；點擊玩家名稱開啟小卡。私人頻道可選取既有對話，或由玩家小卡建立當前頁面新對話；封鎖對象顯示唯讀提示，開啟對話後可清除頁面內未讀。

### 8.2 好友、封鎖與玩家小卡

玩家小卡可發起私人訊息、加好友、加入／解除黑名單、檢舉、贈禮與轉帳。封鎖後要關閉小卡／清單並顯示結果；設定頁可解除封鎖，正式服務需同步關係與通知。

### 8.3 檢舉與客服案件

1. 玩家從小卡開啟檢舉 Modal，填寫原因與補充說明。
2. 無效對象、空原因或已達進行中案件上限時，不建立案件。
3. 成功後建立 `report` 類別案件，第一則訊息包含檢舉對象、原因與補充內容，並切換至客服頻道。
4. 玩家可在案件列表查看全部／進行中／已結案，進行中案件可繼續對話，結案案件唯讀。

目前客服共 7 個類別，seed 案件為 `CS-000001`；同時最多 1 筆進行中案件是前端候選限制，正式規則待確認。

## 9. 頁面狀態

需覆蓋未登入、年齡／資格不足、連線中、離線、載入中、頻道無資料、空對話、輸入錯誤、送出中、送出失敗、禁言、頻率限制、被封鎖、玩家不存在、檢舉成功／失敗、案件上限、案件不存在、已結案、客服回覆未讀、服務中斷與重試。敏感資料需有遮罩與不可見狀態，不能用單一 Mock 成功畫面代替。

## 14. 這個功能需要的資料

- 頻道、訊息 ID／序號、發送者／收件者公開識別、內容、時間、送達／已讀與審核結果。
- 對話 ID、最後訊息、未讀游標、封鎖／好友關係、關係變更時間與通知事件。
- 客服案件 ID、類別、狀態、建立／更新時間、訊息、未讀、附件／敏感資料遮罩與 SLA reference。
- 檢舉對象、原因、補充、來源訊息、時間戳、重複檢舉關聯與後台處理結果。
- `channel`、`receiverId`、返回路徑、客服導流與 `WEB-FLOW-05` 所需的跨頁資料。

目前 `useSocialState.ts`、`useSupportTicketState.ts` 與頁面 `ref` 只代表 Web 原型保存範圍；正式服務需由社交／客服 API 與 WebSocket 提供權威結果。
