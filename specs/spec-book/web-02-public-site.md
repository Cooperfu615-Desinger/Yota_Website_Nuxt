## 1. 這個功能是什麼

讓未登入玩家認識巨亨ONLINE、查看活動與排行榜、閱讀新手教學、了解儲值與客服入口，並在需要會員或大廳功能時導向登入或登入後平台。公開頁與登入後大廳部分共用 `Shared*Content.vue`，但公開頁不可直接暴露玩家私有資料。

目前公開路由為 `/`、`/events`、`/leaderboard`、`/deposit`、`/tutorial`、`/support`。`/member` 目前由 `pages/member.vue` 導向 `/lobby/member`，因此現階段是公開會員入口，不是獨立的公開個人資料頁。

## 2. 這個功能不做什麼

|---|---|

| 登入後的玩家私有資料、錢包與紀錄 | `web-06-member.md`、`web-07-finance.md` |
| 正式 CMS、文章管理與內容審核後台 | 後端／營運後台契約；本章只描述前台消費邊界 |
| 實際支付、儲值入帳與退款 | `web-07-finance.md` 與正式支付規格 |
| 即時排行榜、活動報名與即時得獎播報的服務保證 | API／即時服務契約，尚待確認 |
| Figma 精細色票、字級、間距與素材製作 | `YOTAPLATFO-461` |

## 5. 欄位說明

| 欄位／資料 | 顯示內容 | 限制與目前狀態 |
|---|---|---|
| Banner | 圖片、替代文字、目標路徑或導流行為 | `imageSrc` 可缺省並使用背景 fallback；正式內容應由 CMS 提供 |
| 跑馬燈公告 | 公告文字或得獎提示 | 目前 `siteContent.ts` 含 raw HTML；若改由 API 提供需防止 XSS |
| 活動卡 | 標題、摘要、狀態、日期、獎勵、圖片 | 目前為靜態資料；報名狀態未實作 |
| 排行榜項目 | 名次、名稱、數值、單位、更新資訊 | 目前金額可能是含單位字串；正式 API 應使用結構化數值 |
| FAQ | 分類、問題、答案 | 目前集中於 `siteContent.ts`；文章／版本來源尚待 CMS 定義 |
| 遊戲卡 | 名稱、描述、分類、供應商、圖片、試玩／正式入口 | 遊戲 catalog 的正式來源由 `web-04`／`web-05` 與後端共同確認 |

## 6. 狀態說明

| 狀態 | 目前 Web 行為 | 正式規格要求 |
|---|---|---|
| `active` | 活動目前顯示中 | 由內容／活動服務提供有效期間與狀態 |
| `upcoming` | 活動尚未開始 | 顯示開始時間與不可提前操作的原因 |
| `ended` | 活動已結束 | 保留結果或結束提示，不提供過期操作 |
| `loading` | 多數內容目前沒有真正 loading 來源 | 正式動態內容需定義載入中畫面 |
| `empty` | 主要依靜態陣列是否有資料判斷 | 正式需針對沒有活動、沒有榜單與沒有 FAQ 定義空態 |
| `error` | 目前沒有完整服務錯誤路徑 | CMS／排行榜／活動讀取失敗需定義可重試或導流方式 |

## 7. 查詢、排序與分頁

- 活動目前依 `active`、`upcoming`、`ended` 類別顯示，不是 APP 的 `sale`、`tournament`、`vip` 類型維度。
- 排行榜目前有 `multi`、`win`、`wealth` 三種榜單；更新提示由本地假計時產生。
- 公開頁目前沒有真正的 server-side 分頁、關鍵字搜尋或內容版本篩選。
- 若正式內容量需要分頁，需由 CMS／API 定義 cursor、排序、時區、快取與失敗回應；本章不自行指定。

## 8. 操作與跳轉

| 操作 | 前提 | 目前結果 | 正式待確認 |
|---|---|---|---|
| 點擊首頁 Banner | Banner 有目標設定 | 導向指定頁或執行既有入口 | 是否允許外部 URL、追蹤參數與開新分頁 |
| 點擊活動卡 | 活動資料存在 | 開啟詳情 Modal 或進入內容 | 報名、分享與登入後狀態 |
| 點擊排行榜入口 | 公開頁可直接進入 | 進入 `/leaderboard` | 是否顯示完整即時榜單 |
| 點擊開始遊戲 | 未登入或已登入 | 導向登入／`/lobby` | 年齡驗證觸發點與登入後返回路徑 |
| 點擊儲值 | 未登入或已登入 | 公開頁介紹或導向銀行 | 正式支付前是否必須登入 |
| 點擊客服 | 未登入或已登入 | FAQ 或導向客服頻道 | 未登入是否可建立案件 |
| 點擊 `/member` | 任意身份 | 目前 redirect 至 `/lobby/member` | 是否保留公開會員入口 |

## 9. 頁面狀態

每一個公開頁至少需要在正式內容中確認以下狀態：初始載入、內容載入中、內容成功、無資料、服務失敗、內容停用、登入導流與返回原入口。現有原型主要覆蓋成功與部分無資料情境，尚不能視為完整服務驗收。

## 14. 這個功能需要的資料

- `siteContent.ts` 的 Banner、公告、首頁、活動、排行榜、FAQ、遊戲與教學資料。
- 未來 CMS 的內容 ID、版本、發布狀態、開始／結束時間、圖片、替代文字與目標路徑。
- 排行榜的榜單類型、名次、結構化數值、單位與 `updatedAt`。
- 活動的狀態、有效期間、獎勵、報名狀態與詳情內容。
- 公開頁 SEO title、description、canonical 與分享圖；目前尚未形成完整資料契約。
