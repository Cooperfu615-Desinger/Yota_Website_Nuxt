## 1. 這個功能是什麼

讓已登入玩家查看可用資產、選擇 Web 儲值方案、管理保險箱、兌換金銀幣，以及查看自己的交易紀錄。Web 儲值通道保留平台差異，不直接套用 APP 的 USD／IAP；財務資料必須以正式帳務服務為最終依據。

目前路由包含 `/lobby/bank`、`/lobby/vault`、`/lobby/exchange`、`/lobby/transactions`；`/lobby/deposit` 目前 redirect 至銀行頁。`VaultContent.vue` 目前整合保險箱、贈禮與兌換入口，但贈禮狀態機的詳細規格由 `web-08` 維護。

## 3. 名詞說明

| 名詞 | 定義 |
|---|---|
| 金幣 | Web 主要儲值／遊戲資產；正式價值為 NT$1＝金幣1 |
| 銀幣 | 可與金幣兌換的資產；正式關係為金幣1＝銀幣100 |
| 銅幣 | 無價值試玩幣，不可視為現金或可兌換資產 |
| 保險箱 | 玩家資產的內部保管位置，不是外部提款帳戶 |
| 儲值 | 透過 Web 支付通道建立訂單並等待入帳 |
| 兌換 | 金幣與銀幣之間的內部轉換，手續費目前規格為 0 |
| 交易紀錄 | 玩家可查看的儲值、保險箱、贈禮、兌換、獎勵與消費紀錄 |

## 5. 欄位說明

| 欄位 | 目前內容／規則 | 正式注意事項 |
|---|---|---|
| `balance` | 金幣餘額 | 正式由 `/me/wallets` 或契約提供 |
| `silverBalance` | 銀幣餘額 | 兌換與精度由 server 重驗 |
| `bronzeBalance` | 銅幣餘額 | 只能作試玩資產，不得當作現金價值 |
| `vaultBalance` | 保險箱金幣 | `/vault/withdraw` 是取回主錢包，不是外部提款 |
| deposit plan | 目前有 NT$ 300～10,000 方案候選 | 優惠、付款通道與實際點數需正式契約 |
| amount | 前端輸入金額 | 所有小數無條件捨去，server 必須重驗 |
| transaction type | 目前 `deposit`、`vault`、`gift`、`exchange`、`reward`、`spend` | 三方 enum 需建立對照表 |
| transaction status | 目前 `success`、`processing`、`failed` 候選 | 正式非同步入帳與失敗回滾需定義 |

## 6. 狀態說明

| 狀態 | 目前行為 | 正式規格要求 |
|---|---|---|
| 未登入 | 財務頁顯示登入導引 | 不得讀取或修改財務資料 |
| balance loaded | 顯示前端 state 餘額 | 正式需 server snapshot／更新時間 |
| deposit pending | 目前付款 Modal 以延遲模擬 | 需訂單 ID、processing、輪詢／推送與超時 |
| deposit success | Mock 後寫入餘額／紀錄 | 正式需支付確認與帳務入帳一致 |
| deposit failed | 目前路徑不完整 | 需失敗原因、重試、取消與退款語意 |
| vault transfer | 目前前端直接更新 state | 正式需交易原子性、權限與冪等 |
| exchange | 金銀換算並檢查倍數 | server 需依匯率、餘額與併發重驗 |
| transaction list | 顯示 Mock 列表 | 正式需分頁、時間、狀態與查詢失敗 |

## 7. 查詢、排序與分頁

- 交易紀錄需要正式的 type、status、時間範圍、排序與分頁規格；目前前端僅提供固定 Mock 資料。
- 銀行方案目前以靜態資料呈現，正式需依地區、幣別、會員資格與支付通道查詢。
- 保險箱與兌換是操作型功能，不以前端列表分頁替代帳務查詢。
- 交易排序、時間與時區必須由 API／帳務契約統一，不能混用格式化本地字串與 epoch。

## 8. 操作與跳轉

| 操作 | 前提 | 目前結果 | 正式待確認 |
|---|---|---|---|
| 查看錢包 | 已登入 | 顯示四種餘額 | snapshot、更新與 stale 資料 |
| 選儲值方案 | 已登入／銀行頁 | 開啟付款確認 | 可用通道、優惠與限制 |
| 建立儲值 | 方案與欄位有效 | Mock 延遲後成功 | order、支付、processing、失敗與退款 |
| 存入保險箱 | 主錢包餘額足夠 | 更新 vault／主錢包 state | 原子交易、手續費與錯誤提示 |
| 取回保險箱 | 保險箱餘額足夠 | 更新主錢包 | 明確 `VAULT_OUT`，不可顯示成現金提款 |
| 金銀兌換 | 金額大於 0、銀→金為 100 倍數 | 前端計算並更新 state | 匯率版本、併發與 server 重驗 |
| 查看交易紀錄 | 已登入 | 顯示交易列表 | query、分頁、狀態與資料一致性 |

## 9. 頁面狀態

需定義未登入、餘額 loading、餘額失敗、無交易、交易查詢失敗、方案 loading、方案無資料、付款欄位錯誤、支付處理中、支付失敗、支付取消、餘額不足、兌換倍數錯誤、保險箱操作失敗、重複送出與返回。現有原型對成功路徑覆蓋較多，正式帳務例外尚未驗收。

## 14. 這個功能需要的資料

- 玩家四類錢包餘額、資產更新時間與可用資產狀態。
- Web 儲值方案、NT$ 金額、點數、支付通道、優惠、訂單與支付狀態。
- 保險箱轉移、兌換匯率、手續費、整數運算與交易 reference。
- 交易紀錄 id、type、status、amount、wallet、createdAt、detail 與 referenceId。
- idempotency key、併發版本、失敗原因、退款／回滾與帳務對帳資訊。
